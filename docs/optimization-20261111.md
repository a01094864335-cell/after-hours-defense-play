# 이미지·화면 로딩 최적화 — 2026-11-11

기준: main `426cbe585ace7b5abc08710b5b7bdf89b683eef8`. 승인된 그림체와 화면 구성, 게임 속도·수치·저장 규칙을 유지했다.

## 측정 결과

동일한 390×844 Chromium, 새 브라우저의 빈 캐시, 초기 메인 화면에서 networkidle 후 2.2초 대기, reduced motion 조건이다. 리소스 크기는 Resource Timing의 `decodedBodySize` 합계이며 네트워크 지연 시간이나 실제 휴대폰 FPS를 의미하지 않는다. 이미지 값은 WebP/PNG/SVG 요청의 본문 바이트다. MB는 1,000,000바이트 기준이다.

| 항목 | 적용 전 | 적용 후 | 변화 |
|---|---:|---:|---:|
| 첫 화면 이미지 요청 본문 | 7.547MB | 3.764MB | **50.1% 감소** |
| 첫 화면 전체 리소스 본문 | 8.821MB | 4.992MB | 약 43.4% 감소 |
| 첫 화면 리소스 요청 | 191개 | 175개 | 16개 감소 |
| 재압축한 189개 파일 합계 | 28.889MB | 24.218MB | **4.671MB 절감** |
| 전투 15명 CPU draw 제출 중앙값 | 0.976ms | 0.939ms | 같은 수준, 회귀 없음 |

마지막 수치는 헤드리스 Chromium의 따뜻한 캐시에서 draw 호출을 제출하는 CPU 시간이다. GPU 완료 시간·실제 기기 FPS가 아니며, 작은 차이를 성능 향상률로 해석하지 않는다. 이번 성과의 중심은 첫 화면 로딩과 다운로드 감소다. 이미지 해상도가 같으므로 재압축만으로 디코딩 후 RGBA 메모리가 줄었다고 주장하지 않는다.

## 반영한 변경

1. 성 일지·입사 이야기·일부 UI WebP를 조건부 재압축했다. 파일별 크기와 알파 채널은 그대로 유지한다. 이야기 PSNR 38dB 이상, UI 40dB 이상, 최소 용량 절감 8%를 만족한 **189개만** 적용했다. 기준을 통과하지 못한 파일은 원본을 유지했다. 캐릭터 아틀라스의 좌표·프레임·해시 매니페스트는 건드리지 않았다.
2. 도감·상점·훈련소의 SVG 안에 있는 대형 참조 이미지 `href`를 해당 화면 최초 진입 때 설정하도록 했다. 숨겨진 화면의 그림을 초기 메인에서 받지 않는다. 한 번 로딩한 그림은 브라우저 캐시를 이용한다. 실제 네이티브 `open`/`hidden` 상태와 기존 refresh 경로를 사용하며, 데이터가 같아 렌더를 생략해도 처음 진입하면 그림이 로딩된다.
3. 현재 공통 GNB로 이미 대체된 옛 하단 메뉴 비트맵을 네 화면의 마크업에서 제거했다. 현재 SVG 메뉴·버튼·핸들러는 유지한다. 과거 자료 파일 자체는 삭제하지 않았다.
4. 동일한 바이트의 종이 이미지가 서로 다른 URL로 중복 요청되던 것을 공통 `assets/shared-chrome/paper.webp`로 통일했다. 원본 세 파일의 SHA256이 일치함을 확인했다. 메인 패널·이어하기·전투 스킬 패널에서 공유한다.
5. 메인에서 사용하지 않는 전투판 Image 객체의 idle prefetch를 제거했다. 실제 전투 진입 시 CSS가 같은 그림을 로딩하고, 명시적인 arena API도 유지한다.
6. HTML의 높은 우선순위 이미지 preload를 현재 메인의 배경과 타이틀로 맞췄다. 구 스킨의 우선 preload는 제거했다. 구 로비의 보조 로고에는 비동기 디코딩과 지연 로딩을 지정했다.

스토리 원본 PNG 등 보관용 마스터는 변경하지 않았다. 저장소의 `assets/castle-stories` 디렉터리 크기를 실제 게임 다운로드 크기로 오해하지 않도록 주의한다. 원본 PNG는 기존 배포 스크립트가 이미 제외하고 있다. 오래된 시안·검토 갤러리 파일을 삭제하는 방식으로 수치를 부풀리지 않았다.

## 화질과 화면 확인

`qa/optimization-20261111/images.json`에 모든 변경의 이전/이후 바이트, SHA256, 해상도, 품질, PSNR, 알파 동일 여부를 기록했다. PSNR만으로 지각적 화질을 보장하지 않으므로, 하한에 가까운 스토리 샘플과 로고·종이 애셋의 동일 좌표 확대 비교 및 실제 메인 캡처도 확인했다. 손실 재압축이므로 RGB 픽셀이 완전히 같지는 않다.

`before.png` / `after.png`, `comparison.jpg`, `detail-comparison.png`는 해당 비교 자료다. 새로 그리거나 캐릭터를 교체하지 않았고, 이미지 비율·크롭·텍스트 안전영역·동작은 유지했다.

## 검증과 재측정

- 전체 Node 테스트 3,257개 통과.
- 정식 빌드 브라우저 스모크 36개, 공통 크롬 9개, 훈련 페이지 6개 통과.
- 지연 로딩 회귀 테스트: 처음에는 숨겨진 세 화면 그림과 옛 GNB를 요청하지 않음 → 실제 화면을 열면 올바른 SVG 이미지 로딩 → 메뉴 세 버튼과 닫기 동작 유지.
- 초기 이미지 본문 4.2MB 예산 검사 추가. 3.764MB 측정치에 여유를 둬 일시적 차이는 허용하고 큰 회귀를 막는다.
- `scripts/measure-loading.cjs`: `UI_BASE_URL`, `UI_PERF_OUT`, `UI_SHOT`으로 동일 조건 재측정.
- `scripts/benchmark-battle.cjs`: 전투 CPU 제출 시간 참고 측정.
- `scripts/optimize-images.py`: `/tmp/optimization-before`에 둔 최적화 전 정식 빌드를 입력으로 사용. 동일 원본으로부터만 재압축하며 현재 파일을 반복 압축하지 않는다.

공개 사이트 직접 접속은 이 환경의 프록시 제한으로 403이다. 검증은 정식 로컬 빌드와 GitHub Actions/Pages 배포 결과로 진행하며, 실제 기기 네트워크에서의 로딩 시간은 별도 측정이 필요하다.

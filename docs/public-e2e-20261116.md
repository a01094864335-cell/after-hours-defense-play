## 반복 검사 방법

`scripts/public-e2e-matrix.cjs`는 서로 독립된 저장소를 가진 Chromium 컨텍스트 10개를 순차 실행합니다. 320×568, 390×844, 430×932, 1440×1000, 390×640을 각각 2회 사용하며, 터치 입력과 reduced-motion 설정을 번갈아 검사합니다.

한 회차는 실제 로비 조작·5회 소환·전투 시작·종료 취소/확인, 직원 17명 및 지원 7명의 인사기록, 두 그룹의 훈련, 모든 직원의 실제 고등급 스킬, 지원 동작, 15웨이브 정산 및 새로고침을 포함합니다. 회차별 훈련 기준 레벨은 1–3, 4–6, …, 28–30입니다. 테스트는 현재 공개 UI의 그림자 DOM과 실제 탭·구매 버튼을 사용합니다.

- 각 대상에서 10회 × 6개 흐름 검증 = 60/60 통과.
- 각 대상에서 인사기록 240회, 훈련 기준 상태 60회(두 그룹 각각 Lv.1–30), 실제 구매 58회, 최대 레벨 비활성 검사 2회.
- 각 대상에서 직원 스킬 170회(5·6·7등급을 회차별 변경), 지원 동작 fixture 70개, 정산 및 새로고침 10회.
- 최종 반복의 pageerror, HTTP 오류 및 정상 취소를 제외한 요청 실패는 없습니다. 화면 전환·음악 교체로 취소된 `net::ERR_ABORTED` 요청은 JSON의 `cancelledRequests`에 따로 보존합니다.

자연 진행으로 10판을 완주했다는 뜻은 아닙니다. 보유 상태·재화·훈련·고등급·적·보상은 격리 컨텍스트 안의 명시적 fixture를 사용합니다. 지원 검사에서는 실제 지원 함수를 호출하고 유한한 상태를 확인하며, 회계사는 수입 함수·결계는 돌파 함수를 병행합니다. 모든 지원 수치가 각각의 자연 전투에서 실측됐다는 의미는 아닙니다. 캐릭터의 전투 수치 및 저장 로직은 기존 런타임 회귀 검증을 함께 사용합니다. 사용자 저장기록에는 접근하지 않았습니다.

## 수정한 문제

1. **지원 훈련의 대상과 그림 불일치.** 지원 탭에도 일반 직원 경비원 초상이 고정돼 있었습니다. 직원/지원 탭에 맞춰 기존 경비원/야간 회계사 초상을 동기화하고, 회계사 수치를 `효과 예시`로 명시했습니다. 회계사를 고용하지 않은 경우 `미고용`을 표시합니다. Lv.30에서는 동일한 수치로 향하는 다음 단계 화살표도 제거했습니다.
2. **SP 보상 설명의 기준 불명확.** 전열 정비에서 소환하면 다음 비용은 오르지만 고정된 보상은 계속 `기본 소환 2회분`으로 표시됐습니다. 현재 변주에서 보상은 +150 SP, 소환 후 두 번의 실제 기본 비용 합은 173 SP였습니다. 보상량과 저장 스키마를 바꾸지 않고 `보상 생성 시 기본 소환 2회 기준`으로 설명했습니다. 영어도 생성 시점을 명시합니다.
3. **무료 소환·일일 할증의 화면읽기 가격 오류.** 무료 소환이면서 할인도 남아 있으면 화면은 `무료 소환 · 0 SP`, 접근성 이름은 `50% 할인`으로 읽혔습니다. 무료 소환을 우선 안내하고 유료 할인 유지도 설명합니다. 일반/할인 소환의 접근성 가격 역시 현재 일일 변주가 반영된 실제 가격을 사용합니다.
4. **보상 제목 가독성.** 투명한 제목 뒤로 전투 메시지와 캐릭터가 비쳐 읽기 어려웠습니다. 기존 남색 팔레트의 배경을 제목/안내에 적용하고 여백과 줄 높이를 정리했습니다.

새 그림은 생성하지 않았고 가격·확률·훈련 효과·보상량·밸런스는 변경하지 않았습니다.

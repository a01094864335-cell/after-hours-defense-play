# 마왕성 야간 당직 — 전체 게임 UI 개편

기준 저장소는 `after-hours-defense-play`다. `68e7332` main의 night-watch 전투 아트와 D 레이아웃, 상점 A안, 새 성 이야기 20편을 유지한 상태에서 개편했다.

## 디자인 방향

마왕성 내부에서 야간 당직을 준비하고, 동료를 모으고, 전투를 지휘하고, 근무 보고서를 받는 흐름으로 묶었다. 공통 소재는 보라색 에나멜, 황동 테두리, 금색 주 행동, 청록색 성장 보조 강조다. 전투는 최신 메인에서 승인된 남청색 석재·철제 패널·황동·민트 선택 강조를 보존한다. 설명은 장식 이미지에 넣지 않고 기존 HTML 텍스트로 유지한다.

| 화면군 | 적용 |
|---|---|
| 로비 | 성 배경과 고비를 유지하고 지갑·바로가기·당직 명단·시작 버튼을 금속 콘솔로 정리 |
| 전투·정지 | 최신 night-watch 아트·D 배치·Canvas 좌표를 유지해 다른 화면과 같은 마왕성 세계관으로 연결 |
| 게임 종료 | 고비 보고서 인장, 실제 지급 코인 강조, 상세 기록과 고정 재도전·훈련·로비 버튼 |
| 직원·지원 도감 | 360px 이상에서는 초상 중심 수집 카드 2열, 좁은 화면은 읽기 쉬운 1열. 편성·미보유 상태 유지 |
| 직원·지원 상세 | 정체성 패널·역할·스킬·전기·지원 선택과 채용 행동 유지 |
| 훈련소 | 레벨·실제 성장률·해금 단계와 세부 효과를 성장 기록으로 표현 |
| 장비·편성·개별 아이템 | 재화·비용·보유량과 기존 행동을 유지한 인벤토리 슬롯 형태 |
| 채용팩 상점 | A안 캐릭터 무대와 실제 지원 보장 진행 표시 유지 |
| 이야기·기록·오늘의 변주 | 표지·현재 상태·목록과 상세 내용을 성의 도서관·근무 기록 형태로 통일 |
| 도움말·설정·종료 확인·보너스 | 고정 제목과 닫기·하단 행동, 스크롤 본문을 유지한 공통 패널 |
| 수료 선물·능력 체험·입사 이야기 | 실제 기능과 그림을 유지하고 같은 버튼·헤더·패널 체계 적용 |

## 구현 범위

- `gameworld.css`: 공통 색·재질·아이콘 헤더, 화면별 구성. 기존 핵심 레이아웃 제약 위에 적용한다.
- `gameworld-ui.js`: HTML 루트 스타일 활성화와 실제·동적 생성 대화창에 아이콘 메타데이터만 추가한다. 기존 노드·리스너·상태를 교체하지 않는다.
- `index.html`, `scripts/build-pages.cjs`: 스타일·표시 스크립트 연결 및 배포 파일 포함. 빌드는 기존 방식으로 캐시 해시를 생성한다.
- 게임 규칙·전투 계산·가격·확률·저장·보상·영구 훈련·채용·편성 로직은 변경하지 않았다.

## 전체 화면 검토

[실제 변경 전후 갤러리](../qa/gameworld/index.html)에서 35종 화면을 320×568, 390×844, 430×932로 비교할 수 있다. 105개 기본 캡처와 스크롤 하단 확인을 포함한 개편 후 145개 캡처에 버튼 잘림·문구와 이미지 겹침·가로 넘침·스크립트 오류가 없었다. 원본 PNG는 로컬 캡처로 보존하며, 저장소 갤러리에는 내용이 동일한 경량 WebP 사본을 사용한다.

검토 캡처는 실제 게임을 GM의 격리된 테스트 저장으로 실행한 결과다. 새 인터페이스를 그림으로 그린 시안이 아니며 사용자 저장을 읽거나 수정하지 않았다.

## 검증과 재현

```sh
node --test tests/*.test.cjs
node scripts/build-pages.cjs /tmp/after-hours-gameworld-pages
UI_GAME_ROOT=/tmp/after-hours-gameworld-pages python3 -m unittest discover -s tests -v
UI_QA_DIR=qa/gameworld UI_BASE_URL=http://127.0.0.1:8004/ UI_LAYOUT_AUDIT=1 node scripts/capture-visual-pass.cjs
```

2026-11-09 로직 검사 76개와 전체 브라우저 검사 53개가 모두 통과했다. 브라우저 검사는 실제 전투·합성·스킬·구매·채용·저장·중복 지급 방지·복구·접근성·회전·성능·긴 목록 스크롤을 포함한다.

기존 브라우저 테스트 두 곳은 수정 전 메인에서도 실패했다. 보상은 이미 `#live-result-reward`로 이동했으며 훈련 카드는 `article`이 아닌 `details.training-character`였다. 해당 요소 선택자만 실제 UI에 맞추고 원래의 보상액·중복 지급·최하단 항목 접근성 검증은 유지했다.

이는 로컬 Chromium 검증이며 실제 휴대폰의 체감 성능·브라우저 바·색상은 기기에서 추가 확인할 수 있다.

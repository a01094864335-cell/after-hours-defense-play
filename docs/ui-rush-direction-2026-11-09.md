# 다음 디자인 방향: 직원들이 점령한 마왕성의 우당탕 야간 당직

작성일: 2026-11-09. 기준 구현: `bff164f93be11fac92650030e11da8b43ff95743` / [PR #21](https://github.com/a01094864335-cell/after-hours-defense-play/pull/21).

이 문서는 **다음 디자인 작업의 개선 요구사항**이다. 아래 미술·연출 제안은 아직 게임에 구현하지 않았다. 앞서 완료한 20건은 겹침·정렬·가독성 등 검토 결함의 수정이며, 사용자는 그 결과의 전체 미감과 활기에 만족하지 않았다. ‘20건 수정 완료’를 ‘디자인 최종 승인’으로 해석하지 않는다.

## 사용자가 원하는 인상과 보존할 취향

사용자의 최신 표현은 “좀더 게임스럽게 정신 산만한 느낌이면 좋겠는데”이다. 앞선 요청의 “캐릭터들이 와다다 대소동처럼 모두 보여지는 느낌”과 함께 읽는다. 특정 다른 게임의 자산이나 화면을 복제하라는 뜻으로 해석하지 않는다.

- 방향: 캐릭터들이 와글와글하고, 곳곳에 구경거리와 눌러볼 이유가 있으며, 성 안에서 작은 사건이 계속 벌어지는 인상.
- C 컨셉의 만화적 에너지와 테두리가 두드러지지 않는 열린 장면을 유지한다. 이전의 두꺼운 판넬·프레임 UI로 회귀하지 않는다.
- 캐릭터가 배경 그림 속에만 머물지 않고, 버튼 옆에 기대거나 소품을 운반하고 메뉴에서 고개를 내밀어 UI와 관계를 맺어야 한다.
- 비대칭, 크기 차이, 기울기, 앞뒤 겹침을 더 과감하게 쓴다. 글자·수치·실제 터치 영역은 분리해서 읽고 누를 수 있게 한다.
- 현재 실제 게임의 기능·가격·확률·보장·저장 규칙을 유지한다. 영어판을 고려해 모든 문구는 DOM/CSS로 처리하고 자산에 글자를 굽지 않는다.

## 현재 ‘와다다’ 느낌이 나지 않는 이유

### 1. 캐릭터와 조작 화면이 분리되어 있다

큰 일러스트 한 장을 위에 놓고 아래에 정돈된 메뉴를 나열했다. 그림 안은 붐비지만 그림 밖 UI는 정적이다. 문 옆의 직원, 소환 봉투, 코인 등 게임 속 사물이 사용자의 조작에 반응하지 않는다. 배경을 더 복잡하게 그리는 것만으로 해결되지 않는다. 버튼·목록·보상에도 작은 상황극이 필요하다.

### 2. 모든 화면이 비슷한 크기와 강도로 말한다

옅은 파랑·민트·크림색, 동일한 둥근 버튼, 고른 행 간격이 반복된다. 시작, 채용 성공, 능력 강화, 설정 변경 사이의 감정 차이가 작다. 한 장면 안에서도 주연·조연·소품의 크기 차이가 약하다. 안정적인 배치가 그대로 얌전한 인상이 되었다.

### 3. 정렬을 고치며 화면의 사건도 함께 줄였다

겹침을 없애는 과정에서 캐릭터와 메뉴를 완전히 갈라놓고, 정보와 장식을 넓은 여백으로 분리했다. 필요한 조작 안전 영역과 장식의 겹침은 구별해야 한다. 얼굴·손·소품끼리의 겹침, 버튼 뒤의 캐릭터, 말풍선의 삐져나옴은 의도적으로 허용할 수 있다.

### 4. 현재 화면이 살아 있다는 단서가 약하다

자세 변화, 직원 사이의 시선, 반복되는 소소한 사고, 채용 봉투의 들썩임, 획득 순간의 물리감이 부족하다. 모든 곳을 흔드는 대신 서로 다른 주기의 짧은 행동과 조작 직후의 반응으로 생동감을 만들어야 한다. 새 보상·이벤트가 없는 상태에 가짜 알림을 붙이는 방식은 사용하지 않는다.

### 5. 미술 문법이 장면마다 연결되지 않는다

로비의 SD 만화, 전투의 픽셀 직원, 이야기의 세밀한 장면 그림이 공존한다. 공통 색상만으로는 충분하지 않다. 같은 인물의 표정·비율·핵심 소품·실루엣을 반복해 동일한 세계임을 알려야 한다. 보이는 효과마다 다른 렌더링과 그림자 표현을 쓰면 산만함이 즐거움보다 조잡함으로 읽힌다.

### 6. 기능이 세계 안의 행위로 보이지 않는다

현재 많은 조작이 둥근 사각형 속 텍스트다. 편성은 교대 명단, 채용은 우편 봉투, 훈련은 연습장, 보고서는 쌓인 당직 서류라는 연결이 약하다. 세계관 소품은 기능을 더 빨리 이해시키고 시각적인 농담을 만드는 데 써야 한다.

## 화면별 개선 요구사항

아래 번호는 다음 작업의 추적 번호다. 각 화면의 ‘현재’는 기준 구현의 시각적 진단이며, ‘다음’은 미구현 제안이다. 정상 상태 외에 빈 목록·잠김·재화 부족·최대치·작은 화면도 같은 구성 안에서 다룬다.

### R01. 메인 로비 — `#lobby`

- **현재 / 부족한 이유:** 큰 단체 그림과 그 아래 정돈된 편성·메뉴 영역이 분리되어 있다. 캐릭터들이 UI에 관여하지 않아 정적 포스터와 메뉴를 보는 느낌이다. 넓은 화면에서는 그림과 시작 버튼 사이의 호흡도 길다.
- **다음 구성:** ‘야간 출근 대소동’ 한 장면으로 묶는다. 고비는 출전 버튼 옆에서 명단을 확인하고, 배달부는 채용 메뉴 쪽으로 날아가며, 청소부는 하단 바 근처에서 물을 튀기는 식의 방향성을 준다. 인물·손·봉투·코인이 장면과 메뉴 사이를 이어주게 한다.
- **반응 / 디테일:** 출전 버튼 누름에 고비가 명단을 접고 성문 쪽을 보는 짧은 반응. 대기 중에는 서로 다른 시점의 눈 깜빡임·고개 내밀기·우편 봉투 들썩임 중 한두 개만 재생한다. 닫힌 메뉴 위에 가짜 빨간 점을 상시 붙이지 않는다.
- **유지 기능:** 시작·이어하기·일일 변주 선택·5인 편성·지원 선택·직원 모집·상점·이야기·기록·훈련·설정 진입. 기존 기능을 장면 소품에 연결하고 접근 경로를 없애지 않는다.
- **자산 / 확인:** 단체 그림 외에 투명 배경의 고비·손·봉투·청소 소품 조각이 필요하다. 제목과 시작 버튼은 그림에서 분리한다. 320×568에서도 주요 행동은 처음 보이며, 얼굴·제목·시작 문구가 겹치지 않는지 확인한다.

### R02. 일일 변주 선택·일일 과제 — `#daily-option`, `#daily-events-dialog`

- **현재 / 부족한 이유:** 로비의 얌전한 행과 긴 과제 목록으로 보여 특수한 당직을 고르는 기대감이 작다.
- **다음 구성:** 성 안의 교대 게시판에 붙은 사건 공고처럼 표현한다. 현재 선택된 변주 하나는 큰 도장·상징 소품으로 주목시키고, 나머지는 읽기 쉬운 열린 행으로 정리한다. 규칙별 실제 데이터가 있는 경우에만 맞는 아이콘을 사용한다.
- **반응 / 디테일:** 선택 시 공고가 살짝 들어 올려지고 선택 도장이 찍힌다. 수령 가능한 실제 보상이 있을 때만 코인 더미나 봉투가 들썩인다. 수령 완료 후 빈 알림은 즉시 정리한다.
- **유지 기능:** 변주 규칙 전문, 선택 상태, 진행도, 수령 가능·완료·미달성 구분. 장식 때문에 달성 조건을 접어 숨기지 않는다.
- **자산 / 확인:** 공고 종이·압정·도장·규칙 아이콘을 무문자로 만든다. 규칙이 길거나 과제가 모두 완료된 상태에서도 행 높이와 수령 버튼이 안정적인지 확인한다.

### R03. 근무 명단·편성 — `#deck`, `#deck-open`

- **현재 / 부족한 이유:** 균일한 직원 선택 그리드와 작은 초상은 편성 도구로 읽히지만 다섯 동료를 골라 출근시키는 감정은 약하다.
- **다음 구성:** 출근 대기선에 선 5명과 아래의 교대 후보를 연결한다. 편성된 직원은 큰 자세·이름표, 후보는 더 작은 목록으로 크기 차이를 준다. 서류를 드는 고비나 출근표 소품을 보조로 사용한다.
- **반응 / 디테일:** 교체 후보 선택 → 대상 선택 → 두 직원의 자리가 짧게 바뀌는 반응. 선택한 직원을 장식 뒤에 숨기지 않는다. 현재 편성·선택 후보·제외 대상의 표시를 분명히 유지한다.
- **유지 기능:** 항상 5명을 유지하는 편성 규칙, 프리셋이 있는 경우 저장·불러오기, 미보유 상태와 안내, 완료·뒤로 가기.
- **자산 / 확인:** 기존 초상·모션 시트를 우선 재사용하고 발밑 그림자·출근 도장을 추가한다. 긴 이름, 같은 색 직원, 빠른 연속 선택에서도 잘못 교체되는 느낌이 없는지 확인한다.

### R04. 직원 도감: 채용 직원 — `#roster`, `#roster-tab-staff`

- **현재 / 부족한 이유:** 균등 간격의 작은 인물과 이름·상태가 반복되어 인물의 성격보다 목록 규칙이 먼저 보인다.
- **다음 구성:** 인사기록부를 열어 직원들이 사진 밖으로 튀어나온 느낌을 준다. 인물의 키·자세·소품 차이를 살리되 이름과 상태는 공통 기준선에 둔다. 편성 중인 5명은 출근 도장으로 읽히게 한다.
- **반응 / 디테일:** 선택한 직원만 한 번 손을 흔들거나 직업 소품을 든다. 모든 초상이 동시에 뛰거나 모든 이름표가 기울어지는 방식은 피한다.
- **유지 기능:** 채용/미채용/지원 탭, 보유 수, 편성 상태, 상세 열기. 탭은 스크롤 밖에 유지해 과거의 탭·캐릭터 겹침을 재발시키지 않는다.
- **자산 / 확인:** 기존 모션 활용 + 역할별 작은 무문자 소품. 목록 끝, 많은 보유 직원, 글자 확대에서 초상과 옆 셀 이름이 충돌하지 않아야 한다.

### R05. 미채용 직원 목록 — `#roster-tab-incoming`

- **현재 / 부족한 이유:** 흐린 직원과 잠김 정보가 반복되면 미보유 인물을 만나고 싶은 마음보다 비활성 목록이라는 인상이 강하다.
- **다음 구성:** 아직 도착하지 않은 입사지원 봉투·빈 출근증·실루엣을 활용한다. 공개 가능한 정보만으로 직업 소품과 실루엣 차이를 주어 수집 기대를 만든다.
- **반응 / 디테일:** 상세 진입 때 봉투가 살짝 열리거나 실루엣이 고개를 내민다. 실제로 공개되지 않은 능력·이름을 장식 텍스트로 미리 노출하지 않는다.
- **유지 기능:** 미채용 수, 공개 정책, 채용 경로와 비용 안내, 상세·연습 접근의 기존 허용 범위.

### R06. 직원 상세·고유 스킬 — `#roster-detail`

### R10. 직원 영구 훈련 — `#training-dialog`, 직원 탭

- **자산 / 확인:** 닫힌 봉투·열린 봉투·흩어지는 서류·배달부 손을 별도 무문자 자산으로 준비한다. 320px에서도 가격과 구매 버튼이 처음 보이고 가로 스크롤이 없어야 한다.

- **반응 / 디테일:** 구매 성공에 해당 상품이 인벤토리 방향으로 짧게 이동하고 수량이 변한다. 코인이 부족할 때는 상품 자체를 흔들며 구매 성공처럼 보이지 않게 한다.

- **자산 / 확인:** 상품을 쌓아놓은 무문자 변형과 작은 매대 소품. 가격 명암비 6.39:1 수준의 가독성과 목록 끝 접근성을 유지한다.

### R14. 채용 결과: 신규 직원 / 지원 / 중복 — `#recruit-dialog`

- **현재 / 부족한 이유:** 인물 확대와 확인 버튼 정리는 되었지만 세 경우가 여전히 비슷한 정지 화면이다. 새 동료가 도착했다는 사건의 크기가 작다.

- **자산 / 확인:** 3가지 결과의 무문자 등장 효과·봉투·인물 포즈. 얼굴·이름·중복 환산 문구와 확인 버튼은 절대 겹치지 않게 한다.

### R15. 실제 전투: 준비·진행·선택·쿨다운 — `#battle`

- **현재 / 부족한 이유:** 밝고 희미한 전장, 가지런한 칸, 정적인 하단 조작이 전투의 압박과 소동을 약하게 만든다. 장식이 약한 것과 실제 전투 정보가 약한 것을 구별해서 개선해야 한다.
- **다음 구성:** 성 안 당직 현장의 작은 사고를 전장 바깥 가장자리에 배치한다. 적 이동·공격·명중·직원 행동을 가장 선명하게 하고, 하단 소환은 고비가 급히 직원을 부르는 행위처럼 연결한다. 보드에 채워진 인원 수가 증가할수록 활기를 느끼게 하되 전투 규칙은 그대로 둔다.
- **반응 / 디테일:** 소환의 착지, 합성의 흡수·성공·실패, 스킬의 시선 유도, 적 처치의 짧은 명중 반응을 구분한다. HUD를 계속 흔들거나 모든 캐릭터가 동시에 점프하게 만들지 않는다.
- **유지 기능:** 소환 비용·SP, 생명·웨이브·속도·일시정지, 드래그·선택·합성, 스킬 등급·쿨다운·기절, 장비·소모품·경고 전문 보기·보스 예고. 전투 좌표와 판정은 바꾸지 않는다.
- **자산 / 확인:** 픽셀 전투에는 같은 픽셀 문법의 접지·먼지·명중 효과를 우선한다. 15칸·17종·6포즈·고등급·모든 쿨다운·기절에서 상태 띠와 인접 캐릭터 픽셀의 겹침을 재검사한다. 적 경로에는 배경 소품을 놓지 않는다.

### R16. 전투 아이템 대상 선택·소환 할인 안내

- **현재 / 부족한 이유:** 길어진 안내문과 평소와 비슷한 버튼만으로는 지금 무엇을 선택해야 하는지 순간적으로 약할 수 있다.
- **다음 구성:** 선택한 소모품이 손에 들린 듯 HUD에 나타나고, 실제 선택 가능한 칸만 일관된 표식을 준다. 할인은 현재 실제 가격과 다음 한 번 적용 조건을 함께 보여준다.
- **반응 / 디테일:** 첫 대상·두 번째 대상·취소·유효하지 않은 대상의 반응을 구분한다. 아직 완료되지 않은 합성을 성공 효과로 미리 표현하지 않는다.
- **유지 기능:** 합성권 종류별 조건, 대상 선택·취소, 소모 시점, 할인 한도, 부족 SP, 실패 보상 안내와 정확한 비용.
- **자산 / 확인:** 선택 링·대상 연결선·짧은 소모 효과. 안내 행이 늘어나도 전투 하단과 보드 수치가 겹치지 않고 선택 칸을 가리지 않아야 한다.

### R17. 스킬 컷인·군단장 경고·마왕 등장

- **현재 / 부족한 이유:** 연출 그림이 커져도 평상시 화면과 인물·색·속도의 관계가 약하면 별도 이미지가 덮인 느낌이 난다.
- **다음 구성:** 평소 스킬 아이콘 → 해당 인물의 포즈 → 전장에 적용되는 실제 효과가 시각적으로 이어지게 한다. 군단장 경고와 마왕의 익살스러운 등장·거절은 서로 다른 리듬으로 구별한다.
- **반응 / 디테일:** 경고는 위협의 방향, 마왕은 무게감과 표정, 직원 스킬은 직업 소품을 강조한다. 전체 화면 섬광·진동·과한 흔들림은 선택적이며 감소 모드에서 생략한다.
- **유지 기능:** 실제 스킬 발동 여부, 마왕 사용 조건·거절·등장·잔상 상태, 군단장 능력 경고 전문, 조작 잠금의 현행 규칙.
- **자산 / 확인:** 인물 비율과 외곽 표현이 맞는 무문자 컷인·방사형 효과. 의도적으로 보드를 덮는 연출과 일반 직원 쿨다운의 잘못된 겹침을 따로 검수한다.

### R18. 신입 연수·튜토리얼 대화 — `#tutorial-gobi`, `#guide`

- **현재 / 부족한 이유:** 인물 옆 긴 설명과 버튼이 교육 팝업처럼 보여 게임 속 동료에게 배우는 느낌이 약하다.
- **다음 구성:** 마왕과 고비가 바로 옆에서 당직을 지시하는 상황으로 연결한다. 한 단계에서는 하나의 실제 조작을 지목하고, 인물 표정과 손짓이 그 방향을 가리키게 한다. 읽기 영역은 안정적으로 둔다.
- **반응 / 디테일:** 사용자가 실제 조작을 완료했을 때 짧은 칭찬 표정·도장·상황 반응을 준다. 자동 재생되는 장식 때문에 다음 버튼을 못 찾게 하지 않는다.
- **유지 기능:** 전체 연수 단계·설명 전문·건너뛰기·확인·재개, 소환·합성·아이템·마왕·할인 규칙. 실제 버튼의 색·이름과 안내가 계속 일치해야 한다.
- **자산 / 확인:** 마왕/고비의 기쁨·당황·설명 표정과 지시하는 손. 긴 영문과 가장 긴 대사를 넣어 내부 스크롤과 다음 버튼 접근을 확인한다.

### R19. 당직 장비·직군 강화 — `#equipment`

- **현재 / 부족한 이유:** 선택 가능한 강화가 비슷한 카드와 숫자로 반복되어 ‘지금 전투가 강해진다’는 느낌이 작다.
- **다음 구성:** 직원들이 사용하는 도구를 작업대에 올려놓은 구도. 현재 레벨과 다음 효과를 크게 묶고, 손질·불꽃·체크 표시로 강화의 행위를 전달한다.
- **반응 / 디테일:** 성공한 도구 하나에만 짧은 업그레이드 반응. SP 소비·최대치·사용 불가를 색과 문구로 분명히 보여준다.
- **유지 기능:** 실제 장비 종류·레벨·비용·전투 적용 효과·최대 레벨·부족 SP·닫기 후 복귀. 영구 훈련과 당직 내 강화를 혼동시키지 않는다.
- **자산 / 확인:** 기존 도구 아이콘과 강화 단계 소품. 긴 효과 설명, 최대 레벨, 낮은 SP에서 선택 가능 상태가 명확한지 확인한다.

### R20. 웨이브 보너스·전략·보상 대상 선택 — `#perk`

- **현재 / 부족한 이유:** 아이콘을 달았지만 같은 길이의 문장 행과 옅은 버튼이 계속되어 선택의 즐거움과 보상별 차이가 작다.
- **다음 구성:** SP는 쏟아지는 재화, 생명은 왕좌 방어 표식, 합성 보장은 합성 도구 등 실제 보상별 큰 소품을 주연으로 둔다. 항목은 서로 다른 실루엣을 갖되 주 행동과 선택 경계는 명확하게 한다.
- **반응 / 디테일:** 선택한 보상 하나가 HUD 또는 해당 대상에 도착하는 짧은 반응. 최대 생명·이미 보유 등 선택 불가 상태를 보상 획득처럼 꾸미지 않는다.
- **유지 기능:** 실제 5/15/20웨이브 선택지, 합성 보장·전략·장비/직원 대상 목록·뒤로 가기, 현재 보유와 최대치.
- **자산 / 확인:** 5개 보상 범주별 무문자 소품과 선택 확인 반응. 대상이 17명일 때 목록과 선택 행위를 끝까지 확인한다.

### R21. 일시정지 — `#ref-pause`

- **현재 / 부족한 이유:** 일반 확인 팝업과 비슷해 잠깐 쉬는 상황의 개성과 현재 전투의 맥락이 작다.
- **다음 구성:** 직원들이 잠깐 숨을 고르는 작은 정지 장면을 얹고 전장은 뒤에서 멈춰 있게 한다. 계속하기는 가장 선명한 행동으로 유지한다.
- **반응 / 디테일:** 머그잔·땀방울 같은 작은 정적 소품 위주. 일시정지 중에는 전투처럼 움직이는 배경을 재생하지 않는다.
- **유지 기능:** 계속하기, 근무 안내, 로비 이동과 관련 확인 절차, 현재 웨이브 맥락.
- **자산 / 확인:** 휴식 표정·의자·컵. 일시정지 뒤 전투가 재개되거나 시간이 흐르는 연출 오해가 없는지 확인한다.

### R22. 중도 이탈·확인 — `#leave`

- **현재 / 부족한 이유:** 다른 팝업과 비슷한 외형에서 재개와 이탈의 무게 차이가 약할 수 있다.
- **다음 구성:** 고비가 문 앞에서 붙잡는 작은 상황과 함께 현재 행동의 결과를 짧고 분명하게 읽히게 한다. 장난스러운 그림이 경고 문구를 가리지 않게 한다.
- **반응 / 디테일:** 복귀는 짧은 안도 반응. 이탈의 확인 버튼은 정확한 결과를 읽은 뒤 누를 수 있어야 하며, 실수 유도용 이동 버튼을 쓰지 않는다.
- **유지 기능:** 현재 게임의 이탈·정산·재개 처리와 확인·취소. 손실이나 보상 여부는 현행 로직에 맞춰 명시한다.
- **자산 / 확인:** 작은 문·붙잡는 고비. 가장 긴 안내와 작은 화면에서 두 선택의 문구·터치 영역을 모두 확인한다.

### R23. 게임 종료·정산 — `#result`

- **현재 / 부족한 이유:** 큰 일러스트·보상·통계를 정렬했지만 전투를 함께 끝낸 직원들의 반응과 보상이 들어오는 물리감이 작다.
- **다음 구성:** 쌓인 서류와 쓰러진 직원·기뻐하는 직원이 함께 있는 당직 보고 현장. 보상 코인이 정산 영역으로 모이고, 실제 기록에 근거한 한두 개의 활약 표식을 표시한다. 새로운 MVP 판정 규칙을 만들기 전에는 기존 통계만 활용한다.
- **반응 / 디테일:** 종료 → 실제 보상 확정 → 다음 당직/훈련 선택으로 연결한다. 숫자 카운트는 짧고 건너뛸 수 있게 하며 저장 실패·지급 대기는 성공 축하와 명확히 구분한다.
- **유지 기능:** 웨이브·처치·보상 금액·직원별 기록·당직 분석·다시 시작·훈련·로비·지급 재시도. 이미 지급한 보상을 연출 때문에 다시 지급하지 않는다.
- **자산 / 확인:** 보고서 더미·코인·수고한 인물 포즈. 정상 정산·지급 대기·연수 성공/실패·상세 표 펼침을 별도 검수한다.

### R24. 기록·여정·전투 분석 — `#journey-dialog`, `#run-analysis`

- **현재 / 부족한 이유:** 숫자와 반복 목록이 행정 화면처럼 보이며 플레이 기억을 떠올릴 구경거리가 적다.
- **다음 구성:** 야간 근무 일지를 펼친 구도에 실제 최고 기록·성장·최근 당직의 작은 도장과 소품을 붙인다. 상세 수치 표는 장식과 분리해 읽기 좋은 표로 유지한다.
- **반응 / 디테일:** 실제 신기록이 있을 때만 새 도장을 보여준다. 기록이 없는 경우는 빈 일지와 첫 출근 제안으로 구성한다.
- **유지 기능:** 실제 기록·이전 당직 대비·지원 기여·군단장·돌파·직원별 분석과 모든 상세 펼침.
- **자산 / 확인:** 일지·압정·무문자 기록 도장. 긴 표는 자신의 내부 가로 스크롤만 사용하고 결과 화면 전체를 가로로 밀지 않게 한다.

### R25. 이야기 도감 — `#story-archive`

- **현재 / 부족한 이유:** 표지와 긴 제목이 같은 행으로 반복돼 사건을 모으는 재미보다 읽을 항목 목록이 먼저 보인다.
- **다음 구성:** 마왕성의 사건 기록을 모은 앨범처럼 구성한다. 실제 이야기 범주·획득 상태에 따라 스냅샷과 작은 사건 소품의 크기를 달리한다. 잠김과 다시 읽기의 상태를 분명히 한다.
- **반응 / 디테일:** 새로 획득한 실제 기록에만 새 사진을 끼우는 반응. 모든 표지에 애니메이션을 넣지 않는다.
- **유지 기능:** 현재 40개 이야기의 제목·수집 진행도·잠김 조건·재열람. 목록과 읽기 화면 간 복귀 위치를 존중한다.
- **자산 / 확인:** 기존 표지 재사용과 종이·사진 고정 소품. 표지의 의도된 이미지 자르기와 실제 인접 텍스트 겹침을 구별한다.

### R26. 프롤로그·성 이야기 읽기 — `#promo`

- **현재 / 부족한 이유:** 자세한 장면 그림과 밝은 읽기 UI가 붙어 있지만 로비와 인물·소품의 연결이 약해 다른 게임의 이야기처럼 느낄 수 있다.
- **다음 구성:** 화면을 사건의 한 컷으로 읽히게 하고, 화자·반응·말풍선이 그 컷의 인물과 연결되도록 한다. 이미 충분히 복잡한 장면에는 추가 소품을 줄이고 대사의 리듬을 살린다.
- **반응 / 디테일:** 컷 넘김과 화자 전환을 짧게 연결한다. 본문 전체를 계속 타이핑해 재독을 늦추거나 건너뛰기를 숨기지 않는다.
- **유지 기능:** 모든 페이지와 대사·화자·보조 설명·이전/다음·건너뛰기·도감 재열람.
- **자산 / 확인:** 핵심 인물의 표정·색·소품을 로비와 맞춘다. 그림 속 영문/한글을 추가하지 않고 가장 긴 대사와 이미지 로딩 실패 상태를 검수한다.

### R27. 채용 이야기 — `#hiring-story`

- **현재 / 부족한 이유:** 새 직원 획득의 기쁨과 이야기 화면의 구성 사이가 끊겨 별도의 슬라이드처럼 읽힐 수 있다.
- **다음 구성:** 방금 도착한 직원의 첫 출근 사고로 이어지게 한다. 채용 결과의 봉투·서류·인물 포즈를 첫 컷의 단서로 재사용하고, 마지막 컷은 직원 상세나 근무 명단으로 자연스럽게 연결되는 인상을 준다.
- **반응 / 디테일:** 등장 인물별 짧은 표정 변화와 컷 전환. 신규가 아닌 도감 재열람에서는 첫 획득 보상처럼 보이지 않게 한다.
- **유지 기능:** 실제 채용 이야기의 페이지·대사·이전/다음·닫기·이미지 상태 안내와 획득 처리.
- **자산 / 확인:** 해당 직원과 첫 출근 소품의 일관성. 닫기 아이콘과 페이지 위치를 성 이야기와 같은 규칙으로 유지한다.

### R28. 근무 안내·보스 도감·스킬 도움말 — `#info`, 안내 뷰

- **현재 / 부족한 이유:** 본문과 작은 그림 위주여서 읽기 부담이 먼저 느껴질 수 있다.
- **다음 구성:** 고비가 그린 짧은 실전 예시처럼 구성한다. 소환→합성→스킬, 보스의 주의 행동 등 실제 규칙 하나당 인물·화살표·결과 한 세트를 보여준다. 설명 전체를 새로 그린 이미지에 넣지 않는다.
- **반응 / 디테일:** 필요할 때만 단일 예시를 재생하거나 정적 연속 장면으로 제시한다. 도움말 안에서도 생명·SP·코인 구분을 실제 HUD와 동일하게 쓴다.
- **유지 기능:** 정확한 수치·예외·보스 규칙·스킬 조건·전문 보기·닫기 후 원래 화면 복귀.
- **자산 / 확인:** 무문자 예시 도해와 직업 소품. 긴 설명은 읽기 중심으로 두고 장식이 내용을 잘라먹지 않게 한다.

### R29. 설정·오디오·절전·효과 모드 — `#menu`

- **현재 / 부족한 이유:** 일반 앱 설정과 같은 행·슬라이더가 이어져 게임 세계와의 연결이 가장 약한 화면 중 하나다.
- **다음 구성:** 성의 당직 조정실이라는 작은 테마를 준다. 볼륨은 확성기, 절전은 졸린 램프 등 기능을 직관적으로 설명하는 소품만 사용한다. 조작 자체는 익숙한 설정 UI로 유지한다.
- **반응 / 디테일:** 켬/끔 상태에 소품의 정적 모습이 바뀌는 정도. 오디오 설정 때 허락 없이 큰 소리를 내거나 배경 전체를 계속 움직이지 않는다.
- **유지 기능:** 효과음·BGM 볼륨/음소거, 안내·이야기·훈련 진입, 현재 판 초기화, 절전·간결 효과·백업. 초기화는 다른 일반 설정과 분명히 구분한다.
- **자산 / 확인:** 램프·확성기·책상 소품. 슬라이더 터치, 모든 설정 항목, 파괴적 행동의 의미와 스크롤 끝 접근을 확인한다.

### R30. 저장 백업·기기 옮기기·복구

- **현재 / 부족한 이유:** 코드·입력창·복사·복구가 기술 도구처럼 보인다. 장식을 늘리면 중요한 상태 판단을 방해할 수 있는 화면이다.
- **다음 구성:** ‘근무 기록 보관소’라는 얕은 테마만 적용한다. 서류 봉투와 작은 고비를 배치하고 성공·실패·확인 정보를 가장 잘 읽히게 한다. 이 화면의 소동 강도는 낮게 둔다.
- **반응 / 디테일:** 복사 완료·파일 읽기·유효성 검증·복구 완료에 각각 정확한 짧은 피드백을 준다. 실패 상태에 축하 효과를 쓰지 않는다.
- **유지 기능:** 실제 내보내기·복사·가져오기·검증·복원 확인·오류 안내·저장 안전 장치. 개인정보·백업 값을 장식 텍스트나 공개 캡처에 사용하지 않는다.
- **자산 / 확인:** 무문자 보관 봉투·안전 도장. 긴 코드, 잘못된 데이터, 저장 실패, 복구 취소·확정의 상태를 실제 기능 기준으로 검사한다.

### R31. 다중 탭·저장 오류·회전 안내·로딩/이미지 실패

- **현재 / 부족한 이유:** 긴급 시스템 안내에 게임 장식을 똑같이 적용하면 원인과 필요한 행동이 흐려질 수 있다.
- **다음 구성:** 작은 당황한 고비·정지 표식·기울어진 기기 등 최소한의 세계관 단서만 둔다. 정상 플레이 화면과 구분되는 명확한 안내를 우선한다.
- **반응 / 디테일:** 재시도·다른 탭 정리·회전 등의 실제 해결 동작에만 반응한다. 오류 중 장식이 계속 돌아가서 게임이 정상 진행 중인 것처럼 보이지 않게 한다.
- **유지 기능:** 실제 저장 쓰기 잠금·재연결·충돌 방지·가로 회전 안내·이미지 로딩/실패 안내. 모든 배경 동작과 저장 보호 규칙은 기존 구현을 유지한다.
- **자산 / 확인:** 작은 오류·기기 아이콘과 정적 표정. 실제 두 탭·실제 회전·지연/실패 응답에서 안내를 검수한다.

## 작업 순서와 검수 방법

1. **로비 한 화면에서 미감부터 합의한다.** 정지 시안에 주 사건·작은 사건·버튼/캐릭터 관계·영문 문구 공간을 표시하고, 이어서 짧은 동작 예시를 만든다. 이전처럼 곧바로 전체 화면을 같은 패턴으로 확장하지 않는다.
2. 로비·전투·상점·도감·훈련·종료의 주요 6화면을 같은 캐릭터/소품 언어로 다시 설계한다. 모든 화면을 똑같은 밀도로 만들지 않는다.
3. 실제 상태를 연결한 동작 시안을 검수한다. 재화 부족·잠김·중복·실패·최대치에서도 유쾌함과 상태 신뢰가 함께 유지돼야 한다.
4. 이야기·기록·도움말·설정·백업을 확장한다. 오류·백업·전투 핵심 정보에는 낮은 소동 강도를 유지한다.
5. 기존 결함 20건의 합격 기준을 다시 확인한다. ‘장식의 의도된 겹침’과 ‘문자·조작을 방해하는 겹침’을 캡처와 실제 터치로 구별한다.

새 미감의 승인 기준은 아직 검증되지 않았다. 다음 리뷰에서는 아래 질문에 답할 수 있는 시안과 실제 화면을 함께 제시한다.

- 첫눈에 캐릭터들이 같은 장소에서 무슨 일을 하는지 보이는가?
- 큰 일러스트를 가려도 버튼·목록·보상 자체에 게임의 성격이 남는가?
- 로비·상점·결과가 서로 다른 사건으로 느껴지면서 같은 게임으로 연결되는가?
- 인물과 소품이 UI와 실제로 관계를 맺는가, 단순히 빈 곳을 장식하는가?
- 화면이 바빠도 첫 행동, 보상, 비용, 선택 상태를 바로 찾을 수 있는가?
- 320×568, 390×640, 390×844, 430×932 및 영문·130% 글자·모션 감소에서 같은 의도가 유지되는가?

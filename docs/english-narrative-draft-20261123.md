# 스토리·인사기록 영어 초안 — 2026-11-23

사용자가 QC 도중 스토리·캐릭터 소개까지 영어 초벌 번역을 포함하도록 선택했다. 기존 한국어 원문과 원본 그림은 보존하고, 설정에서 English를 선택하면 표시 문구만 바뀐다.

## 제공 범위

- 마왕성 이야기 40편 × 4장면: 첫 당직 4장면과 성 안 일상 156장면, 총 160장면의 제목·화자·대사·나레이션.
- 입사 이야기 19편 × 4장면: 총 76장면의 제목·대사와 이름·직무. 둘을 합치면 고유 이야기 장면은 236개다.
- 캐릭터 24명: 이름·직무·부서·소개·한마디·성격·역할·기본 능력·스킬·스킬 설명.
- 스토리 목록, 해금/다시보기 안내, 그림 로딩/실패 안내, 인사기록의 조작 문구와 탐색 레이블.
- 320px에서 긴 마지막 버튼은 `Done ✓`, `Prepare →`, `Archive →`로 축약했다. 대사는 기존 스크롤 구조에서 읽고, 그림과 조작 버튼을 유지한다.
- 출시용 최종 감수 전의 영어 초안이다. 다른 일부 게임 UI 문구는 여전히 한글일 수 있으므로 설정 안내도 이 실제 범위에 맞췄다.

## 구현과 상태 보존

`narrative-en.js`는 약 39KB의 표시용 초안 데이터다. `narrative-locale.js`가 원문 문자열과 연결해 기존 `GameLanguage` 번역기에 등록한다. 스토리·인사기록 노드만 관찰하며 게임 전체의 프레임별 텍스트를 감시하지 않는다. 숫자·판정·소유권·등장 확률을 번역 데이터로 계산하지 않는다.

한국어 원본 `CastleStories`, `HIRING_STORIES`, `staffRecords`를 영어로 덮어쓰지 않는다. 언어 전환 때 다시 보상을 지급하거나 다음 장면으로 넘기지 않는다. 새 콘텐츠에 번역이 빠지면 원문을 유지하고, 전체 번역 누락 검사가 릴리스 전에 이를 잡는다.

## 추가로 발견해 고친 스토리 전환 문제

닫기 직후 다른 이야기를 열면 이전 창의 비동기 `close` 이벤트가 뒤늦게 도착할 수 있었다. 이 이벤트가 새 이야기의 `castleReplay`를 해제해 다음 장면의 안내문을 비우거나, 새 스토리를 읽는 도중 `comicResume`를 해제하고 전투를 재개할 수 있었다.

현재 스토리가 다시 열려 있다면 이전 닫기 처리를 무시하도록 스토리 상태·전투 재개·로딩 표시의 세 지점을 수정했다. 닫기→즉시 다시 열기를 한 이벤트 흐름 안에서 재현하는 회귀 검사로 다시보기 상태와 일시정지 유지, 마지막 실제 닫기 시 정상 재개를 확인한다.

## 검증

- 최종 로컬 런타임 3,335개 전부 통과.
- 모든 현재 스토리·화자·인물 필드에 한글 잔존 여부를 검사한다. 능력과 스킬 설명의 모든 숫자도 원문과 비교한다.
- 성 이야기 160장면을 320×568에서, 입사 이야기 76장면을 320×568과 390×844 각각에서 실제 이전/다음 조작으로 검사한다. 고유 장면 수 236과 반복 화면 관찰 횟수를 혼동하지 않는다.
- 24명 인사기록을 실제 도감 카드로 열어 Story 탭의 소개·인용문과 뒤로 조작을 확인한다.
- English→한국어→English 전환 후 대사·페이지 위치가 복원되고, 원본 이야기·인물·보유 자산·보드·SP·가격이 변하지 않는지 확인한다.
- 각 브라우저 검사에서 JavaScript 오류도 확인한다.
- 영어 저장 후 재접속·언어 왕복·오디오/저장 보존 검사 3개도 통과했다. 공통 GNB는 번역된 탐색 이름으로도 생성되어야 하므로 한국어/영어 둘 다 인식한다.
- 최종 CI는 기존 132개와 새 4개를 합친 136개 시나리오를 각각 10번, 총 1,360회 실행한다. 이 숫자는 자연 플레이 10판 완주를 뜻하지 않는다.

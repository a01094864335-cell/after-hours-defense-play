# 적군 크기 비교와 공개 반영

## 결론

일반 적 5종은 기존보다 **35% 확대**, 군단장 7종은 **최대 12% 확대**한다. 화면 가장자리와 긴 무기 때문에 공간이 부족하면 전체 6포즈가 들어오는 크기로 제한한다. 390px 화면의 일반 적 기준 높이는 약 27px에서 36px로 바뀐다. 320px에서는 약 22→30px, 430px에서는 약 29→40px다.

| 비교안 | 캡처 검토 | 결정 |
|---|---|---|
| 기존 | 보드 직원에 비해 적의 얼굴과 직업별 실루엣이 작음 | 비교 기준 |
| 일반 적 +25% | 안정적이지만 변화가 상대적으로 작음 | 보류 |
| 일반 적 +35% | 얼굴과 장비가 잘 보이고 보드 직원과의 크기 위계도 유지됨 | 채택 |
| 일반 적 +50% | 작은 화면·밀집 상황에서 좌측 이동로가 많이 붐빔 | 제외 |

[네 가지 크기 비교 캡처](../qa/enemy-size-20261111/size-comparison.webp). 실제 게임 화면을 나란히 놓은 비교표이며 캐릭터나 UI를 합성해 만든 화면이 아니다.

## 캡처 조건

320×568, 390×844, 430×932에서 각 후보를 실행했다. 동일 난수 시드로 실제 소환 5회와 게임 엔진 `update(1/60)` 360회를 실행해 **실제 첫 웨이브 전투**를 캡처했다. 비교 조건을 맞추기 위해 렌더링 크기만 후보별로 교체했다. 별도로 보드 15명·적 17명 밀집 상태와 군단장 7종 동시 표시를 검수용 극단 상황으로 캡처했다. 군단장 7종 동시 표시는 정상 진행 규칙이라는 의미가 아니다.

후보 4개 × 화면 3개 × 장면 3개 = 36개 캡처를 비교했다. 최종안은 소스 교체 없이 **공식 배포 빌더가 만든 패키지**로 동일 9개 장면을 다시 캡처했다. 원시 조건·엔진 스냅샷·브라우저 오류 기록은 `qa/enemy-size-20261111/candidate-results.json`, `final-results.json`에 저장했다. 모든 캡처의 브라우저 오류는 0건이다.

공개 Pages 직접 열람은 실행 환경 프록시 제한이 있으므로, 현재 공개 배포와 같은 코드를 로컬에서 실행해 캡처했다. 공개 반영은 병합된 메인 커밋의 Pages 배포 작업 성공으로 확인한다.

## 크기와 경계 처리

- 확대는 `BattlePresentation`의 화면 투영 단계에만 적용한다. 적의 실제 위치, 이동 속도, 체력, 사거리, 공격·돌파 판정, 보상, 저장 형식은 유지한다.
- 원화의 6포즈 전체에서 좌/우/상단 최대 범위를 한 번 계산해 캐시한다. 걷기·공격·피격 포즈가 바뀔 때마다 크기가 흔들리지 않게 한다.
- 좌우 화면 가장자리에는 2px 여유를 두고, 상단에는 체력바·이름표용 20px를 확보한다. 긴 무기와 비대칭 포즈도 기준점에서 양쪽을 따로 계산한다.
- 전체 너비는 `min(60px, 화면 너비 15%)` 이내다. 군단장을 화면 중앙에서 키울 수 있어도 가장자리에서 무리하게 잘라내지 않는다. 예를 들어 390px 좌측 경로에서는 캐릭터에 따라 약 47~52px 높이가 된다.
- 기존 보드 직원 17종, 지원 얼굴 배지와 마왕 연출 크기는 유지한다. 새 이미지나 추가 다운로드는 없다.

## 검증

- 일반 적·군단장 12종 × 6포즈 × 3화면 × 경로 5지점의 전체 범위 검사: 화면 좌우와 상단 여유 검증.
- 일반 적 +35% 및 군단장 확대 상한 검증.
- Chromium 실제 전투 렌더를 가로채 표시 높이를 측정하고, 그리기 전후 저장 스냅샷이 동일함을 확인했다.
- 전체 런타임 회귀와 GitHub Actions의 모달 캡처·브라우저·반복 기능 검사를 배포 전 실행한다.

재현: `python scripts/capture-enemy-size.py /tmp/enemy-size-review`. 최종 배포 패키지 그대로 캡처하려면 `UI_GAME_ROOT=/tmp/enemy-size-pages python scripts/capture-enemy-size.py /tmp/enemy-size-final --final`.

# 전체 게임 E2E 및 디자인 기능 기획 개발 점검

검토 기준은 main `0d10fbf859093baae17b869ba68a281bd311c49a`입니다. 자동 회귀 검증과 별도로 실제 브라우저 캡처 및 상태 전환을 확인했습니다. 자동 검증이 통과해도 화면 일부의 가림, 번역 누락, 잘못 읽히는 안내까지 해결됐다는 뜻은 아닙니다.

게시 시점의 main에는 이후 변경인 #50(직원 윤곽선 통일, `1af3472`)이 포함되어 있습니다. 아래 수치와 캡처는 검토 기준 `0d10fbf`의 기록이며, #50 이후 변경의 재검증 결과로 사용하지 않습니다.

## 검증 범위와 결과

- **기능 E2E: 111개 시나리오 × 10회 = 1,110/1,110 통과.** 26개 브라우저 테스트 모듈, 5개 작업이 각각 2반복을 수행했습니다. 재시도·건너뛰기·미실행·fixture 오류는 없습니다.
- **런타임 로직: 3,287/3,287 통과.** 저장·정산·구매·전투·보상·기술 효과 등의 기존 검증을 포함합니다.
- 반복 검증에서 격리 브라우저 컨텍스트 1,850개를 만들었습니다. 실제 지정 뷰포트는 320×568부터 1280×900까지 9종이며, 그중 터치 에뮬레이션 컨텍스트는 20개입니다. 추가 모달 캡처는 별도의 터치 컨텍스트를 사용합니다.
- 탐색 검토는 한·영 × 320×568·390×844의 68개 화면 상태, 별도 4크기 × 2언어의 메인 좌표·hit-test, 지원 훈련·영문 안내 재현을 포함합니다. 탐색 68개 상태에서 수집한 pageerror는 0건입니다.
- 직원 17명과 마왕·적·지원 20종의 대표 포즈·초상 비교를 별도로 수행했습니다.
- 추가 화면 목록 검사는 **50개 상태 × 4개 크기 = 200개 조합**을 끝까지 시도했습니다. 최초 결과는 193개 성공, 시간 초과 7개로 원본 suite는 실패입니다. 기능 반복 종료 후 같은 8초 제한으로 대상 7개를 별도 재검증했고 7개 모두 캡처·검사를 통과했습니다. 최초 실패를 삭제하거나 처음부터 200개 통과로 바꾸지 않았습니다. 6개는 페이지 진입, 1개는 세션 준비 대기 시간 초과였고, 마지막 1개는 캡처 작업의 중지·재개 이후 발생했습니다. 두 결과를 합치면 200개 조합 모두 성공한 캡처·기하 검사를 확보했지만, 동시 부하에서의 불안정 원인이 영구 해결됐다는 판정은 아닙니다. ## 먼저 처리할 재현 문제

### F01 메인 수료 선물 버튼 하단이 다른 버튼으로 가려짐

- 우선순위 P1. 한글·영문 모두 320×568에서 재현했습니다. 연수 수료 후 첫 동료 선물을 아직 받지 않아 세 번째 바로가기가 표시되는 상태입니다.
- 수료 선물의 영역은 y=143–187, 오늘의 변주는 y=178–222로 **9px 겹칩니다**. 수료 선물 버튼의 아래쪽 90% 지점(y=182.6)을 hit-test하면 수료 선물이 아니라 오늘의 변주 버튼이 잡힙니다. 중앙은 눌리므로 중앙 클릭 테스트만으로는 놓칩니다.
- 390×684, 390×844, 430×932의 두 언어에서는 같은 겹침이 발생하지 않았습니다.
- 개선: 바로가기 3개가 있을 때 필요한 높이를 레이아웃에 포함하고, 좁은 화면에서는 로고·장식 영역을 줄이거나 선물을 독립 슬롯으로 이동합니다. 44px 터치 영역을 줄여 해결하지 않습니다.
- 완료 기준: 선물 유무 × 두 언어 × 네 화면 크기에서 형제 버튼 교차가 0이고 최소 8px 간격을 확보합니다. 버튼 중앙뿐 아니라 네 모서리 안쪽도 올바른 버튼으로 판정되어야 합니다.
- 근거: [geometry.json](../qa/full-e2e-audit-20261112/geometry.json), [ko-320-lobby.png](../qa/full-e2e-audit-20261112/ko-320-lobby.png), [en-320-lobby.png](../qa/full-e2e-audit-20261112/en-320-lobby.png). 관련 코드: `previews/asset-lobby-20261109/lobby.css`의 `.a-shortcuts`, `.a-bottom`, `.a-daily`.

### F02 보상 재배치 중 소환하면 SP 안내가 실제 소환 횟수와 달라짐

- 우선순위 P2. 5웨이브 보상에서 다음 기본 소환 비용이 60 SP이면 카드가 `+130 SP · 기본 소환 2회분 · 할인 전`으로 생성됩니다.
- 전열 정비로 들어가면 소환 버튼이 활성화되어 있습니다. 실제 소환을 1회 하면 SP는 500→440, 보드 인원은 5→6, 다음 기본 비용은 60→70으로 바뀝니다.
- 보상으로 돌아와도 카드는 +130 SP와 2회분을 그대로 표시합니다. 이 시점의 두 번 소환 비용은 70+80=150 SP입니다. 한·영 × 320·390의 네 번 탐색에서 모두 재현했습니다.
- 지급 수치 자체는 고정 보상과 일치합니다. 문제는 고정된 금액을 현재 시점의 소환 횟수처럼 설명하는 데 있습니다.
- 개선: 보상 생성 시점의 금액을 유지한다면 `SP +130 · 보상 생성 시 기본 소환 2회 기준`처럼 기준을 명시하거나 수치만 표시합니다. 정비를 이동 전용으로 정할 경우에는 소환·강화 허용 정책을 먼저 결정해야 합니다. 재배치를 반복해 보상이 계속 커지는 방식은 피합니다.
- 완료 기준: 비용 변동·할인·무료 소환·재진입·저장 후 재개에도 문구가 지급 내용과 일치하고 중복 지급이 없어야 합니다.
- 근거: [explore.json](../qa/full-e2e-audit-20261112/explore.json)의 `reward-reposition-summon` 네 항목, [ko-390-reward-before.png](../qa/full-e2e-audit-20261112/ko-390-reward-before.png), [ko-390-reward-after.png](../qa/full-e2e-audit-20261112/ko-390-reward-after.png). 관련 코드: `progression.js`의 `perkReward`, `rewardCopy`, `rewardBundle`; `tactical-duty.js`의 `startReposition`.

### F03 지원 영웅 훈련 화면에 일반 직원 얼굴이 고정됨

- 우선순위 P2. 실제 훈련소 진입 후 지원 영웅 탭을 클릭해 확인했습니다.
- 본문은 `지원 영웅 전체`, `회계사 기본 정산 2.00→2.02 SP`인데 우측 초상화는 `assets/character-portraits/goblin-guard.webp`, 즉 일반 직원 브릭입니다.
- 훈련 그룹의 수치 오류로 확인된 것은 아닙니다. 그룹을 대표하는 그림과 설명의 대상이 달라지는 문제입니다.
- 개선: 직원 탭에는 직원 단체 배지, 지원 탭에는 지원 영웅 단체 배지를 쓰거나 현재 대표로 보여주는 지원 영웅과 초상화를 함께 바꿉니다. 회계사 수치만 그룹 전체의 대표 효과처럼 제시하지 말고 `효과 예시 · 회계사`라고 표시하거나 현재 보유 지원의 전후 효과를 우선합니다.
- 완료 기준: 탭 전환 시 그룹명·대표 초상·설명 대상이 일치하고 소유하지 않은 영웅의 예시라는 점도 구별됩니다.
- 근거: [focused.json](../qa/full-e2e-audit-20261112/focused.json), [en-320-support-training.png](../qa/full-e2e-audit-20261112/en-320-support-training.png), 모달 캡처의 `training-merc`. 관련 코드: `concept-people.js`가 초상화를 `goblin-guard`로 고정 생성합니다.

### F04 영문 설정이 영문 출시 품질에 도달하지 못함

- 영어 출시 전에는 P1, 한글판만 대상으로 하면 P2인 기존 범위의 부족입니다. 언어 선택 자체의 저장·재진입·게임 데이터 보존은 회귀 검증 대상으로 삼았습니다.
- English를 선택해도 상점의 채용팩/개별 아이템/확률/구매 문구, 직원·지원 이름과 역할, 훈련 효과, 근무 안내 본문, 스토리 본문, 전투 소환 버튼 등에 한글이 남습니다. 메인이나 공통 버튼의 일부 영어화와 전체 콘텐츠 번역은 구별해야 합니다.
- 예: 상점 제목은 `Night shift shop`인데 탭은 `채용팩`, 구매는 `120 코인 · 채용팩 열기`; 훈련 제목은 `Training room`인데 설명은 `지원 영웅 전체`, `회계사 기본 정산`입니다.
- 개선: 모든 사용자 노출 문구를 번역 키로 관리하고 수치·영웅 이름·복수형을 조합합니다. 영어 스토리, 접근성 이름, 실패·저장 오류·빈 상태도 같은 목록으로 관리합니다. 이미지에 문자가 포함된 부분은 언어별 그림 또는 문자가 없는 그림+CSS 텍스트로 분리합니다.
- 완료 기준: 영어 화면 순회 시 허용된 고유명사를 제외한 한글 잔존이 없고, 게임 데이터나 보유량을 바꾸지 않고 언어를 왕복할 수 있어야 합니다.
- 근거: [explore.json](../qa/full-e2e-audit-20261112/explore.json)의 영어 화면 텍스트와 캡처들. 한글 글자 수는 탐색 지표이며 화면에 실제 보이는지 캡처와 대조했습니다.

### F05 짧은 영문 탭도 단어 중간에서 줄바꿈됨

- 우선순위 P2. 320×568의 근무 안내에서 `Basics`, `Merge`, `Battle`, `Bosses`가 `Basi/cs`, `Merg/e` 등의 형태로 갈라집니다.
- 탭 폭은 각각 61.25px, 글자는 16px이며 `overflow-wrap:anywhere`가 적용됩니다. 터치 영역이 확보돼도 읽기 좋은 영문 레이아웃은 아닙니다.
- 개선: `Guide / Merge / Fight / Boss`처럼 짧은 표기를 검토하고 탭의 좌우 패딩을 조정합니다. 일반 영단어에 anywhere를 쓰지 않고, 긴 고유명사만 별도 줄바꿈 정책을 둡니다. 가독성을 낮추는 일괄 글자 축소는 피합니다.
- 완료 기준: 네 크기, 두 언어, 큰 글자 설정에서 단어가 잘리지 않고 선택 상태도 명확해야 합니다.
- 근거: [focused.json](../qa/full-e2e-audit-20261112/focused.json), [en-320-help.png](../qa/full-e2e-audit-20261112/en-320-help.png). 관련 코드: `single-screen-settings.js/css`의 안내 탭 스타일과 공통 줄바꿈 정책.

### F06 초기 메인에 필요하지 않은 이미지도 함께 로드됨

- 우선순위 P2. 캐시가 없는 격리 브라우저에서 로컬 공식 배포 패키지의 메인 진입만으로 **192개 리소스, transferSize 합 5,137,407bytes, decodedBodySize 합 5,079,807bytes**를 기록했습니다. 이미지 요청은 82개입니다. 공개 CDN 압축이 적용된 실측값은 아닙니다.
- 초기 요청에는 현 메인 배경 외에 `open-scene`의 lobby/shop/training/result 그림, 이전 로고와 메인 그림도 포함됩니다. 네 open-scene 그림만 약 675KB입니다. 화면을 방문하기 전에 발생한 요청이라는 점이 핵심입니다.
- 원인 후보를 넘어 소스에서도 `open-scene.js`, `lobby-duo.js`, 여러 후속 표현 모듈이 기존 그림을 추가·교체하는 흐름을 확인했습니다. 일부 그림은 후속 화면에서 쓰이므로 파일 삭제보다 첫 표시 시점으로 로딩을 늦추는 것이 우선입니다.
- 개선: 현재 메인을 구성하는 이미지 우선 로드, 상점·훈련·종료 그림은 첫 진입 시 로드, 폐기된 표현 계층의 초기 실행 제거. 공통 그림은 하나의 경로로 캐시를 공유합니다.
- 완료 기준: 같은 패키지·콜드 캐시 조건에서 요청 목록 및 바이트를 전후 비교하고, 화면 전환 시 빈 그림·폰트 깜빡임이 없어야 합니다. 실제 네트워크와 기기에서 별도의 LCP·입력 지연·메모리·발열 측정을 수행합니다.
- 근거: [resources.json](../qa/full-e2e-audit-20261112/resources.json). 회귀 테스트에서의 프레임·캐시 검증 통과를 실제 저사양 기기 성능 인증으로 확대 해석하지 않습니다.

### 공통 디자인 기준 제안

레이아웃 조정의 시작값으로 카드 내부 12–16px, 같은 정보 묶음 사이 8px, 다른 묶음 사이 16–24px를 적용하고 화면별로 검토합니다. 본문은 14–16px와 1.45–1.6행간, 짧은 보조 라벨은 12px 이상을 기준으로 삼습니다. 이는 이번 측정 결과의 전역 합격선이 아니라 다음 수정의 디자인 기준 제안입니다. 실제 길이가 긴 영문·오류·최대 수치를 넣어 예외를 조정해야 합니다.

버튼 터치 영역은 최소 44px, 화면 가장자리와 고정 CTA에는 안전 영역을 확보합니다. 그림의 장식 프레임 바깥에 들어오는 것만 확인하지 말고, 프레임 안쪽의 시각적인 여백까지 확인합니다. 정보가 길어지면 문구 축약→구조 조정→의도된 스크롤 순서로 해결하며 전체 화면의 폰트를 한 번에 줄이지 않습니다. 검은 윤곽선이나 그림 테두리를 더 두껍게 추가하기보다, 배경 명암·면의 색·영역 간격으로 위계를 만듭니다.

## 기획에서 보강할 점

### P01 첫 지원 영웅까지의 목표를 더 짧게 설명

현재 채용팩은 120코인, 지원 확률은 10%, 미보유 지원의 보장은 10팩입니다. 팩만 이용하고 포인트 지정 채용·초기 지급·스토리 보상을 제외하면 첫 지원까지 기대 팩 수는 `(1-0.9^10)/0.1=6.513`, 지출은 약 782코인입니다.

기본 생성 적을 전부 처치하는 15웨이브 한 번의 단순 계산은 일반 적 240명·보스 3명으로 39코인입니다. 보스의 추가 소환·각종 보너스·조기 패배를 제외한 예시이며 실제 평균 수입이나 소요 시간을 측정한 값은 아닙니다. 이 예시에서는 120코인이 약 3.1회 정산에 해당합니다. 따라서 첫 지원을 기다리는 구간은 초보에게 길게 느껴질 가능성이 있습니다.

우선 가격을 바꾸기보다 `다음 지원 보장까지 N팩`, 포인트 지정 채용까지 남은 양, 지원의 역할을 메인·도감·상점에 연결합니다. 이후 실제 첫 지원 획득 시간·연수 이탈·사용 비율을 측정해 첫 체험 지급 또는 첫 보장 간격을 검토합니다. 현재 무료 수료 선물은 일반 직원 선택이므로 지원 영웅 체험과 구별됩니다.

### P02 이야기 수집의 후반 중복 체감

첫 이야기를 본 뒤 나머지 39개에서 균등 무작위로 뽑고 이미 본 이야기를 제외하지 않습니다. 이상적인 독립 추첨에서 39개를 모두 모으는 데 필요한 기대 추첨은 `39×H39≈165.9회`이며, 첫 고정 이야기와 별개인 이론값입니다. 완주 보장 횟수는 없습니다.

수집을 주요 목표로 삼는다면 미수집 가중치나 N회 중복 후 새 이야기 보장, 캐릭터별 일지 선택권을 검토합니다. 반복 등장 자체는 세계관 연출로 유지하되, 새로운 이야기를 기다리는 진행감은 별도로 보강하는 편이 좋습니다.

### P03 다음 5웨이브 목표와 보상의 의미

세 장 보상의 상한·대상 보정·저장 보존은 기능적으로 검증하지만, 선택의 재미는 별도입니다. 장비·직원·합성 보험·SP를 많이 받아도 플레이어가 어떤 전략을 만들고 있는지 읽히지 않으면 숫자 교체처럼 느껴집니다.

`즉시 운영 / 편성 성장 / 다음 구간 대응`의 의미를 카드 문구에 유지하고, 대체 보상도 왜 이 선택이 나왔는지 이해할 수 있게 합니다. 보상 때문에 선택지가 세 개를 넘거나 새 영구 성장 체계를 추가할 필요는 없습니다. 후반 적 체력 상승과 임시 +10~20% 효과의 체감을 실제 15/30/45웨이브 도달률·선택률·선택 후 생존 구간으로 비교해야 합니다. 무한 진행에서 결국 패배하는 것 자체는 오류가 아닙니다.

### P04 종료 화면에서 다음 행동으로 연결

마지막 돌파 적 이름, 적 잔여 HP, 직원별 피해·처치·수입 데이터가 이미 있습니다. 단순 기록 나열보다 `남은 HP가 적었다 → 화력 보강`, `초반 빈 자리 다수 → 소환 운영`처럼 근거 있는 짧은 팁으로 연결할 수 있습니다. 정밀한 추천이 어려우면 관찰 사실만 보여주고 원인을 단정하지 않습니다. 코인으로 가능한 훈련 또는 다음 채용 목표도 함께 제시합니다.

## 개발과 QA에서 보강할 점

1. **부분 가림을 잡는 검사**: 현재 크기·조상 클리핑·중앙 클릭만으로 F01을 못 잡습니다. 핵심 버튼의 교차 면적과 다중 지점 hit-test를 검사합니다. 투명 장식의 시각적 교차와 실제 클릭 방해는 구분합니다.
2. **상태를 넘나드는 카피 검사**: 보상 생성→정비→소환/강화→복귀→저장 후 재개의 숫자·문구 일치를 검사합니다. 현재 카드 개수·대상 유효성 검사와 별개입니다.
3. **그룹과 이미지의 의미 검증**: 단순 이미지 로드 성공 외에 직원/지원 탭에서 대표 `data-character-id`나 그룹용 이미지가 올바른지 검증합니다.
4. **번역 커버리지와 실제 영어 폰트 검사**: 저장 기능과 일부 버튼 번역만 통과해도 출시 커버리지가 충족되는 것은 아닙니다. 화면별 문구 목록, 잔존 한글 예외, 영문 버튼의 단어 중간 줄바꿈을 검사합니다.
5. **표현 계층 정리**: 기존 화면을 만든 뒤 여러 모듈이 DOM·그림·스타일을 다시 바꾸는 흐름은 F06의 초기 요청 낭비와 연결됩니다. 현재 사용 화면의 생성·상태 갱신 책임을 모으고 이전 표현 모듈을 순차 제거합니다. 일괄 대개편보다 화면 단위로 동일한 기능 계약을 유지합니다.
6. **성능 검사의 목적 분리**: 픽셀 크기·캐시·30/60fps 설정 검증과 실제 기기의 안정적인 프레임 유지·긴 플레이 발열은 다릅니다. 초기 로딩 예산, 조밀한 전투, 화면 왕복 후 메모리, 15분 이상 플레이를 별도 측정합니다.
7. **과도한 동시 실행에서의 테스트 시간 초과**: 5개 기능 반복 작업과 추가 캡처를 한 머신에서 함께 돌렸을 때 캡처 작업의 8초 페이지 진입 제한에 걸린 기록이 나왔습니다. 원본 실패를 보존하고 단독 재현 결과를 따로 기록합니다. 타임아웃을 늘려 통과만 만드는 대신 CI 자원과 동시 작업 수를 조정합니다.
8. **브라우저와 실기기 범위**: 이번 10회는 Chromium입니다. 실제 iOS Safari에서 주소창 높이 변화, 안전 영역, 세로/가로 전환, 터치 드래그, 백업 가져오기, BGM 재개를 확인해야 합니다. 기존 CI의 일부 WebKit 모달 검사는 전체 기능의 Safari 10회 검증을 대신하지 않습니다.
9. **실제 플레이 지표**: E2E 통과만으로 가격·난이도·재미를 확정하지 않습니다. 첫 전투 시작, 연수 수료, 첫 합성·스킬·지원, 15웨이브 정산, 첫 채용까지의 단계별 이탈과 시간을 수집해야 기획 조정의 근거가 생깁니다.

## 증거와 재실행

- 기능 반복의 원본 결과는 `qa/full-e2e-audit-20261112/functional-shard-0.json`부터 [functional-shard-4.json](../qa/full-e2e-audit-20261112/functional-shard-4.json)까지이며 각 실행의 상태·뷰포트·시간·실패 정보를 보존합니다. 집계는 같은 폴더의 [functional-summary.json](../qa/full-e2e-audit-20261112/functional-summary.json)입니다.
- 런타임 로그, 탐색 화면 텍스트, 좌표·hit-test, 초기 요청 목록과 핵심 캡처를 같은 폴더에 보관했습니다. 그림 비교표는 런타임 매니페스트의 첫 프레임과 대응 초상에서 만든 검토용 표입니다.
- 원본 모달 목록 검사는 [modal-original.json](../qa/full-e2e-audit-20261112/modal-original.json), 대상 별도 재확인은 [modal-recheck-summary.json](../qa/full-e2e-audit-20261112/modal-recheck-summary.json)으로 구분합니다. 별도 재확인을 최초 성공으로 바꾸지 않습니다. 보조 재현 스크립트 작성 중 전체 카탈로그와 부분 실행 목록의 충돌로 난 두 번의 도구 오류도 로그를 보존했으며, 게임의 실패로 집계하지 않았습니다.
- 같은 커밋을 체크아웃하고 `node scripts/build-pages.cjs /tmp/audit-game`으로 패키지를 만든 뒤 `UI_GAME_ROOT=/tmp/audit-game GITHUB_SHA=<commit> FEATURE_QA_DIR=<output> FEATURE_QA_SHARD=<0..4> python tests/run_feature_qa.py`를 실행합니다. 다섯 shard가 각각 두 반복을 맡습니다. 로컬에서 무거운 캡처까지 동시에 실행하기보다 CI의 분리된 머신이나 순차 실행을 권합니다.
- 런타임은 `node --test tests/*.test.cjs`, 전체 모달은 `UI_GAME_ROOT=/tmp/audit-game MODAL_QA_DIR=<output> python -m unittest discover -s tests -p 'test_modal_inventory.py' -v`로 확인합니다. 이번 로컬 머신에는 WebKit 실행 파일이 없어 해당 엔진은 검증 결과에 넣지 않았습니다.

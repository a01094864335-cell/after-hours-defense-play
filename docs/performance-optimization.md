# 발열 완화 업데이트

모바일(터치 기기 또는 폭 600px 이하)은 기본 절전 모드 30 FPS, 데스크톱은 60 FPS로 실행한다. 당직 메뉴에서 절전 모드를 켜거나 끌 수 있고 선택은 기기에 저장한다. 게임 배속 1/2/3배와 화면 FPS는 별개다.

## 적용 내용

1. 전투 HUD의 주기 갱신은 최대 초당 10회로 제한한다. 입력으로 인한 갱신은 즉시 실행한다. 값이 같은 DOM 텍스트·속성은 다시 쓰지 않고, 닫힌 상점·훈련소는 재구성하지 않는다.
2. 화면은 30/60 FPS 정책을 따르며, 전투 계산은 실제 시간 기준 초당 60회 고정 간격으로 진행한다. 배속은 계산에 적용한다. 장시간 지연 뒤 몰아서 실행하는 계산은 제한한다.
3. 절전 로비와 일시정지는 변경 사항이 있을 때만 그린다. 숨긴 탭은 타이머와 RAF를 취소하고 복귀 시 경과 시간을 따라잡지 않는다. 60 FPS 모드의 로비 초상화는 최대 12.5 FPS로 갱신한다.
4. 보드 배경·경로·고정 문구를 별도 캔버스에 캐시한다. 일반 모드의 조명 그라디언트도 한 번 생성한다.
5. 초상화는 표시 크기와 DPR에 맞춰 비트맵을 만든다. DPR은 최대 1.5, 절전 최대 192px, 일반 최대 320px로 제한한다. 같은 포즈·해상도·이미지 상태는 재사용하고, 가려진 초상화는 생략한다. 이미지 로드·스크롤 진입 시 다시 그린다.
6. 보스 경고의 보드 크기는 리사이즈 때 계산한 값을 사용한다. 그리기 중 레이아웃 측정을 제거하고 보스 HUD의 요소 참조와 변경 값을 재사용한다.
7. 절전 모드에서는 장식 조명·부유 효과·연기·잔상·일부 CSS 애니메이션과 배경 블러를 줄인다. 공격, 피격, 보스 위험 표시와 체력·스킬 상태는 유지한다.

배속 중 자동 저장도 게임 시간 대신 실제 플레이 시간 5초 간격으로 실행한다. 기존 보상·반값 소환·튜토리얼·저장 형식은 유지한다.

## 비교 측정

Chromium 헤드리스, 390×844 화면에서 시나리오마다 새 브라우저 컨텍스트를 만들고 초기 로딩 후 3초간 측정했다. 전투는 적 1명과 직원 1명의 동일한 고정 조건이다. 수치는 실행 환경에 따라 달라진다.

| 3초간 작업 | 변경 전 | 절전 모드 적용 후 |
| --- | ---: | ---: |
| 전투 캔버스 그리기 | 180 | 90 |
| 전투 sync 호출 | 180 | 28 |
| 전투 renderProgress 호출 | 360 | 28 |
| 전투 DOM 변경 레코드 | 9,180 | 180 |
| 일시정지 캔버스 그리기 | 180 | 0 |
| 정지한 로비 프레임 콜백 | 179 | 0 |

전투 그리기는 약 50%, DOM 변경은 약 98% 감소했다. 전투 계산 횟수는 동일하게 180회를 유지했다. 원본 데이터는 [before.json](performance/before.json), [after.json](performance/after.json)에 보관한다. 이 결과는 작업량 측정이며, 실제 휴대폰 온도·전력 사용량은 측정하지 않았다.

## 확인

기존 보상·배속·반값 튜토리얼·저장 보호·사용성 테스트에 성능 회귀 테스트를 추가했다. FPS 제한, 1/2/3배 전투 시간, 정지 화면, 숨긴 탭 복귀, 비트맵 재사용, 대화상자 초상화 표시, 닫힌 상점 갱신 생략과 보스 경고의 레이아웃 측정 제거를 확인한다.

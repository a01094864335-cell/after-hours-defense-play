## 목적과 현재 상태

새 플레이 화면과 연결되는 미술·UI 완성도를 게임 전체에 적용하기 위한 작업 범위다. 탭·상세·결과·팝업·예외 상태까지 포함한다. 아래 항목은 **디자인 작업 및 검수 대상**이며, 모든 항목에서 결함이 발견됐다는 뜻이 아니다. 이번 문서 작성에서는 화면 구조와 기존 요구사항을 확인했으며 전체 화면의 신규 캡처 검수는 수행하지 않았다.

플레이 기본 화면은 승인 시안 좌표, 글자 없는 전용 배경, 실제 DOM 조작부와 전투 Canvas로 재구성했다. 메인·도감·상점·훈련소에는 기존 디자인과 애셋이 적용되어 있지만, 새 플레이 화면과 연결되는 품질로 재검토해야 한다. 기존 작업을 미구현으로 간주하거나 전부 다시 그릴 필요는 없다.

## 유지할 방향과 기능

캐릭터가 와글와글하고 작은 사건이 벌어지는 만화풍 마왕성을 지향한다. 캐릭터가 버튼 옆에 기대거나 소품과 상호작용하도록 구성하되, 글자·수치·터치 영역을 침범하지 않는다. 동일한 사각 컨테이너와 강한 테두리를 반복하기보다 색 덩어리·소품·앞뒤 관계로 화면을 나눈다. 새 플레이 화면의 색·그림·버튼 반응을 공통 기준으로 삼되 모든 화면을 전장처럼 만들지는 않는다.

- 실제 게임 기능·가격·확률·보장·재화·저장 규칙 유지. 화면을 채우기 위해 기능이나 가짜 알림을 추가하지 않는다.
- 영문판을 고려해 문구·가격·수량은 DOM/CSS로 처리한다. 애셋에 글자를 굽지 않는다.
- 메인의 얼굴 중심 표현과 캐릭터 정체성을 유지한다. 전투 보드는 전신, 하단 아이템은 이름 없이 아이콘·수량으로 표시한다.
- 고비는 현재 채택한 외형을 유지한다. 찌릿은 기존 이야기의 주황 점박이 도마뱀·번개 안전모·보라 작업복·꼬리를 기준으로 맞춘다.
- 기존 적군과 공격·피격·합성·지원·마왕 이펙트를 우선 활용한다. 부족하거나 어울리지 않는 부분만 보강한다.

공통 버튼·팝업·문자 규칙은 1단계부터 잡아 각 묶음에 적용한다. 화면을 진행하며 기능을 가리거나 입력이 막히는 문제를 발견하면 순서와 관계없이 먼저 수정한다.

## 공통 검수 기준

1. **인물 일치:** 메인·편성·도감·상점·이야기·전투에서 얼굴, 피부/털 색, 머리, 복장, 핵심 소품을 비교한다. 새 그림과 기존 그림을 나란히 확인한다.
2. **화면 구성:** 승인 시안과 실제 캡처를 같은 비율로 비교한다. 주요 영역 위치·크기·시선 순서·배경 비중을 확인한다. 실제 게임 수치나 배치가 시안 예시와 다른 것은 구분한다.
3. **겹침과 정렬:** 텍스트끼리, 애셋과 텍스트, 가격과 버튼, 목록 그리드, 스크롤 끝, 팝업 헤더/푸터를 확인한다. 장식의 의도적 겹침이 터치나 정보 가독성을 해치지 않아야 한다.
4. **반응형:** 320×568·390×640·390×684·390×844·430×932에서 캡처한다. 긴 화면, 작은 화면, 안전 영역과 브라우저 높이 변화도 확인한다. 가로에서는 회전 안내와 일시정지가 정상이어야 한다.
5. **영문·긴 문구:** 문구는 이미지에서 분리한다. 긴 이름·설명·수치와 글자 크기 130%에서도 잘림과 버튼 침범이 없어야 한다. 실제 영문 번역 적용 시 별도 검수한다.
6. **상태별 확인:** 정상·선택·비활성·잠김·빈 목록·재화 부족·최대치·로딩·성공·실패·저장 오류 중 해당되는 상태를 각각 확인한다. 불가능한 상태를 화면용으로 추가하지 않는다.
7. **입력·접근성:** 실제 버튼과 장식 위치 일치, 모바일 터치, 키보드 포커스·닫기·탭 이동을 확인한다. 아이콘 전용 버튼에도 접근 가능한 이름을 제공한다. 핵심 터치 영역은 44px 이상을 기본으로 한다.
8. **움직임:** 눌림·획득·강화·선택 반응은 짧고 명확하게 한다. 여러 반복 효과가 동시에 경쟁하지 않게 하며 `prefers-reduced-motion`에서도 결과를 이해할 수 있어야 한다.
9. **성능·애셋:** 기존 압축 아틀라스·효과를 재활용한다. 새 원본은 보관하고 배포는 적정 크기·압축 형식으로 분리한다. 누락 이미지·불필요한 중복 요청·화면 전환 끊김을 확인한다.
10. **기능 보존:** 실제 구매·편성·훈련·보상·이어하기·저장/복원 흐름이 디자인 변경 후에도 동작해야 한다. 가격·확률·보장·보유량은 실제 데이터와 일치해야 한다.

## 화면별 완료 기록 형식

각 작업에서 다음을 남긴 뒤 위 체크표를 갱신한다.

- 작업 ID와 적용 화면·상태
- 기준 시안 및 수정 전/후 캡처 경로
- 재활용·추가·교체한 애셋과 원본/배포 경로
- 확인한 화면 크기와 입력·기능 검사 결과
- 발견한 문제, 수정 내용, 남은 제한
- 반영 PR·커밋과 배포 확인 결과

현재 체크표는 전부 미완료다. 이는 후속 디자인 작업의 완료 기록이 아직 없다는 의미이며, 현재 게임 기능이나 기존 화면 구현이 없다는 의미는 아니다.

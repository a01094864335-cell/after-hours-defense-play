# UI 문구 정리 및 E2E 5회 점검

기준 공개 버전: `a9939e0`. 화면의 기능을 설명하는 문장은 줄이고, 같은 화면의 제목·숫자·버튼이 이미 알려주는 내용은 반복하지 않는다. 비용, 확률, 환급, 손실, 자동 저장, 취소 방법은 유지한다. 이야기 대사·캐릭터 설정과 전투/재화 규칙은 변경하지 않는다.

## 검증 방식

- 정식 Pages 패키지를 로컬에서 실행한다. 공개 호스트 직접 접근이 제한된 환경이므로 브라우저 E2E와 공개 배포 성공은 구분한다.
- 기능 시나리오마다 새 브라우저 컨텍스트를 사용하는 `tests/run_feature_qa.py`로 **5회** 반복한다. 전체 통과 여부뿐 아니라 시나리오별 회차·실패·캡처를 기록한다. 자동 재시도로 실패를 숨기지 않는다.
- 실행: `FEATURE_QA_TOTAL_ATTEMPTS=5 FEATURE_QA_SHARD=<0|1|2> UI_GAME_ROOT=<패키지 경로> FEATURE_QA_DIR=<출력 경로> python tests/run_feature_qa.py`. 각 샤드는 1–2회 / 3–4회 / 5회를 담당한다. 기존 CI 기본값 10회는 유지한다.
- 한글·영문 320×568 / 390×844의 실제 주요 화면에서 텍스트와 캡처를 대조한다. 실패 안내도 별도로 확인한다.
- 기존 드래그 버리기 검사가 좌표를 읽기 전 실제 canvas의 actionability/stability를 기다리도록 보완했다. 마우스 드래그·버리기 검증 자체는 그대로다.

최종 회차별 결과와 화면 자료는 `qa/copy-review-20261123/`에 정리한다.

한·영 18개 상태 × 2개 화면 크기 = **72개 캡처**를 [화면 자료](../qa/copy-review-20261123/screens/)에 보관했다. 변경 전 비교는 [before](../qa/copy-review-20261123/before/), 렌더링된 문구는 [screen-copy.json](../qa/copy-review-20261123/screen-copy.json)에 기록한다. 화면 자료는 제어된 테스트 상태이며 실제 이용자 저장을 쓰지 않는다.

## 5회 반복 중 발견한 검사 시간 의존성

원본 반복 기록의 2회차에서 군단장 퇴장 검사 한 건이 좌표를 읽기 전에 알림이 숨겨져 실패했다. 테스트가 남은 시간을 0.39초로 지정한 뒤 0.36초 CSS 퇴장을 기다리는 동안 실제 프레임 시계도 남은 시간을 소비한 것이 원인이다. 게임의 정상 종료를 유지하고, 격리된 검사에서만 알림 시계를 수동으로 구동하도록 보완했다. 일시정지·오른쪽 퇴장 좌표·숨김 검증은 유지한다. 첫 실패는 원본 E2E 보고서에 보존한다.

최종 영문 보완본은 설정 → 영문 선택 → 상점 → 확률 설명 → 실제 구매 → 입사 이야기(있으면 닫기) → 재접속의 **5개 흐름**으로 별도 검증했다. 가격 차감 1회, 저장, 언어 유지, 확률/보장 숫자, 설명창 가로 넘침과 포커스 복귀를 확인했다. [구매 흐름 보고서](../qa/copy-review-20261123/purchase-journeys/report.json). 임시 검증 스크립트에서 입사 이야기의 존재 여부를 잘못 가정한 두 경우는 스크립트 분기만 보완했으며 게임 코드는 바꾸지 않았다.

# 모바일 인게임 보드 공간 개선

2026-11-06. 게임의 600×600 좌표, 15칸 배치, 적 경로와 합성 규칙을 유지한다.

## 구현

- 지원 영웅의 이름과 설명은 유지하고 초상화와 주변 여백을 정리했다.
- 하단 조작부 간격과 외곽 패딩을 줄였다. 소환/장비 48px, 아이템 46px 버튼 높이는 유지한다.
- 캔버스는 두 축을 같은 비율로 확대한다. 장식 크롭은 월드 좌표 기준 좌우 각각 최대 12, 위 40, 아래 12다. 캔버스가 아닌 `.board-stage`가 장식을 잘라낸다.
- 높이가 부족할 때 잘리는 위쪽 영역을 보스 안내 HUD의 위치에 반영한다. 적의 이름, 체력바, 배치 칸과 하단 지원 표시는 보이는 영역 안에 둔다.
- 기존 포인터 변환은 실제 캔버스 사각형을 기준으로 하므로, 음수 x 위치와 위쪽 크롭에도 같은 좌표계를 사용한다.

## 준비 화면 실측

지원 영웅 ‘비상 대응반’을 장착한 Chromium 모바일 뷰포트. 브라우저 주소창 등은 뷰포트 바깥이다. 단위 px, 캔버스의 한 변이며 화면 밖 장식 크롭을 포함한다.

| 뷰포트 | 변경 전 | 변경 후 | 증가 |
| --- | ---: | ---: | ---: |
| 320×568 | 246 | 269 | 9.3% |
| 360×640 | 318 | 348 | 9.4% |
| 375×667 | 293 | 362 | 23.5% |
| 390×740 | 366 | 406 | 10.9% |
| 390×844 | 390 | 406 | 4.1% |
| 430×932 | 430 | 447 | 4.0% |

390×740 이상에서는 보드가 가로폭을 채운다. 짧은 화면은 조작부 가독성을 보존하기 위해 완전한 가로 채움을 강제하지 않는다. 320×568에서는 좌우 여백이 각각 37px에서 약 25.5px로 줄어든다. 지원 설명 줄 수, 메시지, 아이템 안내, 안전 영역 높이에 따라 실제 크기는 달라진다.

## 검증 및 증거

- `node --test tests/*.test.cjs`: 54개 통과.
- 배포 빌드 `test_browser_smoke.py`: 8개 통과. 튜토리얼, 전투 시작/일시정지, 저장 복원, 회전 등을 검사한다.
- `scripts/check-board-space.cjs`: 여섯 크기에서 각각 15칸 터치, 실제 CDP 터치 드래그 합성, 5회 소환, 일시정지/재개, 캡처 및 보이는 월드 경계를 검사한다. 합성 성공 여부는 원래 게임 확률에 따른다.
- `capture-visual-pass.cjs`와 `ui-layout-audit.cjs`: 세 크기의 전체 화면/스크롤 상태 133개에서 버튼 이탈, 텍스트 넘침과 겹침을 검사한다.
- `qa/board-space/before.json`, `after.json`: 여섯 크기의 영역 실측.
- 대표 준비/전투/보스 화면 PNG를 함께 보관한다. 자동 검사와 별도로 대표 캡처를 눈으로 검토한다.

재현:

```sh
python -m http.server 8840
UI_BASE_URL=http://127.0.0.1:8840/ node scripts/check-board-space.cjs
```

Chromium 경로는 `UI_CHROMIUM_PATH`, 증거 폴더는 `UI_QA_DIR`로 지정할 수 있다.

## 검사와 증거

- 기존 브라우저 시나리오는 각 10회 독립 반복한다. 5개 샤드가 각각 2회를 담당하며 자동 재시도로 실패를 덮지 않는다. 시작 인벤토리 124개 × 10회 = **1,240회 전부 통과**. 모든 시나리오에 시도 번호 1..10이 정확히 한 번씩 존재하며 fixture error도 없음을 집계했다.
- 최종 수정본의 Node 런타임 검사 **3,334/3,334 통과**. 제한된 실행 환경의 하위 빌드 프로세스 문제를 구분한 뒤, 빌드 가능한 환경에서 전체 검사를 완료했다.
- 수정 문제용 브라우저 회귀 검사 8개는 모두 통과했다. 각 시나리오가 새 컨텍스트를 사용한다. 최종 CI 인벤토리는 이 8개를 포함한다.
- 화면 직접 점검: 수정 전 102상태(한글/영문 × 320·390·1440px × 17화면), 수정 후 68상태(한글/영문 × 320·390px × 17화면). 두 점검 모두 pageerror 0건. 메인·설정·도움말·군단장 안내·상점·아이템·직원/지원 도감·직원/지원 훈련·스토리·전투 선택·버리기 확인·장비·룰렛·재배치·결과를 포함한다.
- 공개 경로 통합 여정 10회 / 60검사 통과: 5개 화면 크기에 한글/영문을 배분하고, 설정 언어 선택 → 아이템 구매 및 정확한 코인 차감 → 지원 도감 → 훈련 구매 → 네이티브 소환 5회 → 일시정지/복귀 → 버리기 → 새로고침/이어하기 → 보상 지급/중복 차단 → 패배/정산/로비 복귀/재로드를 검사했다.
- 위 통합 여정은 튜토리얼 완료·400코인·10웨이브 보상·패배 상태를 명시적으로 주입한다. ‘자연 플레이로 10판 완주’나 모든 보스를 실제 시간으로 처치했다는 뜻이 아니다. 전투·확률·저장 경계는 별도 런타임 및 브라우저 시나리오로 검사한다.
- 재현 로그, 원본 반복 결과, 전후 비교 캡처 및 검증 집계는 [증거 폴더](../qa/public-qc-20261123/)에 보관한다. 각 로그의 실패가 제품 재현인지 테스트 입력 오류 / 실행 환경 제한인지 아래 증거 설명을 따른다.
- `touch-events.log`는 touchEnd에 종료할 접촉점을 보내야 한다는 실제 이벤트 순서 증거다. 보조 손가락을 종료하는 테스트 입력을 수정했으며 제품 실패를 재시도로 숨긴 것이 아니다.
- 공식 빌드와 하위 프로세스가 필요한 Node 검사는 허용된 실행 환경에서 진행했다. 제한된 샌드박스의 빌드 하위 프로세스 실패는 제품 결함과 구분한다.

## CI 후속 확인 — 드래그 관찰 순서

첫 PR의 132개 × 10회는 모두 통과했다. 첫 메인 실행 `45099157259`는 1,319회 통과 / 1회 실패로 배포가 중단됐다. 실패는 `test_drag_to_trash_frees_cell`의 7번째 시도에서 삭제 전 `#board-trash.bounding_box()`가 `None`을 반환한 것이다. 다른 9회는 통과했다. 원본 샤드 JSON과 실패 화면을 증거 폴더의 `main-first-run-*`로 보존한다.

원래 검사는 raw mouse 이벤트를 보낸 직후 동기식으로 버튼 좌표를 읽었다. raw mouse 전송은 locator 조작처럼 UI 준비를 자동으로 기다리지 않는다. 제품의 드래그 상태가 실제 `from===0 && moved`가 되고 버튼이 visible일 때만 좌표를 읽도록 검사를 보강했다. 지연 원인을 단정하거나 기존 실패를 성공으로 덮지 않는다. 이벤트를 다시 보내거나 보드/버튼 상태를 강제로 설정하지 않으며, 실제 드래그가 시작되지 않으면 5초 안에 계속 실패한다. 이 후속 변경은 테스트와 증거 문서만 수정한다.

추가 재현에서는 원래 좌표 읽기 방식으로 새 컨텍스트 80회를 관찰해 실패 0회였고, 준비 조건을 보강한 검사는 독립 10회 모두 통과했다. 로그를 함께 보관하며, 수정 후 전체 CI에서도 재검증한다.

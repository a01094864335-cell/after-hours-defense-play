# 실제 플레이 기반 디자인 정리

2026-11-02 · after-hours-defense-play

## 실제 플레이

게임의 구매·훈련·도감·직원 선택·소환·배속·장비·일시정지·보너스 버튼을 실제 브라우저에서 클릭했다. 전투의 웨이브/생명/승패를 조작하거나 시뮬레이션 시간을 강제로 올리지 않았다. 기존 3배속 기능을 사용했다.

- 첫 실행: 400코인 GM 임시 데이터로 시작, 직원 훈련 1회와 등급 합성권 구매 후 5명 소환. 5차 보너스에서 1차 관찰을 마쳤다.
- 수정 후 실행: 같은 클릭 흐름으로 전투를 진행하고, 실제 보너스 선택을 거쳐 **14차·왕좌 생명 0으로 종료**, **25코인 보상 결과**를 확인했다.
- `play-log.json`, `play-after-log.json`에 실제 진행 관찰과 오류를 기록했다. 두 실행은 무작위 소환 결과가 달라 성능/밸런스 비교 자료가 아니다. 실행 오류는 없었다.
- GM은 임시 기록·초기 코인과 해금에만 사용했다. 실제 사용자 세이브를 사용하거나 변경하지 않았다.

## 디자인 변경

1. 같은 채도의 보라색으로 벽처럼 보이던 패널을 어두운 자주색으로 낮추고, 내용 카드/배경/행동 버튼의 층을 구분했다.
2. 선택 탭과 현재 GNB에 따뜻한 자주색 면과 금색 글자를 사용하고, 비선택은 차분하게 낮췄다.
3. 로비 근무 명단의 이름·역할·현재 근무 정보를 더 읽기 쉽게 정리했다.
4. 상점 장식 이미지를 줄이고, 짧은 화면에서는 장식을 숨겨 가격과 상품 설명이 먼저 보이게 했다. 구매 알림의 색과 여백을 정리했다.
5. 직원 도감의 개요에서 숨겨진 뒤로 버튼이 아이콘 스타일 때문에 다시 표시되던 문제를 CSS로 바로잡았다. 직원 이름/직무/편성 상태의 크기·대비를 구분했다.
6. 장비 카드 안에 또 버튼이 있는 것처럼 보이던 가격 영역을 일반 정보로 정리했다. 훈련 캐릭터별 이름·해금·잠김 정보도 색과 행간으로 구분했다.
7. 전투의 상단 HUD와 하단 알림은 시선을 덜 빼앗도록 낮추고, 사용할 수 있는 소환/아이템이 상대적으로 강조되게 했다.
8. 결과 화면의 캐릭터와 모션 캔버스 규격을 맞춰 캡션 겹침을 막고, 보상·기록의 공간을 확보했다.
9. 변주 목록의 닫기 기호가 프레임 밖에 표시되는 문제를 텍스트 하나의 중앙 정렬로 고쳤다. 좁은 화면의 편성 저장은 명시적 2줄 부품을 사용한다.

모든 수정은 CSS와 UI SVG/PNG에 한정한다. 새 기능, 게임 규칙, 가격, 합성 확률, 보상, 저장 구조, 조작 흐름은 변경하지 않았다. 실행 HTML과 배포 파일 목록에는 새 스킨 로드만 추가했다.

## 증빙과 검증

- [플레이 화면 비교](index.html): before/after는 실제 플레이 중 캡처다. after/14-result.png는 실제 14차 패배 결과이며, 이후 최종 캐릭터 크기 보정은 full-audit/after/*/32-result.png에서 확인한다.
- full-audit는 UI 상태 fixture를 사용한 **32개 상태 × 3개 크기**와 스크롤 하단 캡처다. 실제 플레이 로그와 구분한다. 모든 스토리·캐릭터 조합을 개별 플레이한 것은 아니다.
- Chromium 모바일 320×568 / 390×844 / 430×932. 최종 주요 화면의 버튼 넘침·화면 이탈·실행 오류 자동 검출 0건.
- `node scripts/check-play-design.cjs`: 숨겨진 버튼 유지, 선택 탭 식별, 모션 캔버스/캡션 충돌 회귀 확인.
- `node --test tests/*.test.cjs`: 30개 통과. Pages 빌드 통과.
- `node scripts/play-design-review.cjs`: 실제 클릭 기반 플레이 재현. UI_BASE_URL / UI_CHROMIUM_PATH 설정 가능. Playwright/Chromium 필요.

iOS Safari 실기기 검증은 포함하지 않는다.

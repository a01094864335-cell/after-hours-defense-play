# 모바일 UI 1차 시각 검수

2026-11-02 · 실제 소스 after-hours-defense-play · B 에나멜 스킨 적용 이후 검수

[수정 전후 전체 비교](index.html). 이미지 원본은 before/after의 320·390·430 폴더, 모아보기는 각 sheets 폴더에 있다.

## 범위와 방법

Chromium의 모바일 viewport 320×568, 390×844, 430×932에서 실제 화면을 캡처하고 원본과 모아보기를 직접 확인했다. 최종 32개 UI 상태 × 3개 크기 = 96개 기본 캡처에 긴 목록의 하단 캡처를 추가했다. 수정 전 130장, 수정 후 141장을 기록했다. 후속 보너스 선택·경고·스토리 변형은 수정 후에 추가하여 수정 전 이미지가 없다.

로비, 메뉴/음량 설정, 기록/편성 보관함, 직원·지원 훈련소, 채용·미채용·지원 도감, 직원·지원·미채용 상세, 채용팩·아이템 상점, 채용 결과, 편성, 백업, 이야기 도감, 오프닝 첫 장/마지막 장, 일상 이야기, 변주 목록, 도움말, 준비·전투, 장비, 일시정지, 포기 확인, 안내, 보너스·직원 선택, 군단장 경고, 결과를 포함한다. 모든 이야기 76장과 모든 캐릭터의 조합을 개별 캡처한 것은 아니다.

GM 임시 데이터로 999,999코인·해금·지원 동료와 전투/결과 상태를 구성했다. GM 패널만 숨겼으며 실제 사용자 저장 데이터는 사용하거나 수정하지 않았다. 캡처 전 포커스를 해제해 프로그램 클릭 때문에 나타나는 키보드 포커스 선을 제외했다. 키보드 focus-visible 표시는 유지한다. 긴 목록에서 상단 일부 카드가 잘리는 것은 내부 스크롤 상태이며 장식 프레임은 고정되어 있다.

## 발견과 수정

| 발견 | 수정 |
|---|---|
| 변주 목록 버튼이 우측 화면 밖으로 이탈 | 텍스트 flex 영역을 축소 가능하게 하고 44px 바로가기 영역 확보; 빈 프레임 대신 화살표 복원 |
| 상점 코인과 아이콘이 프레임 위·오른쪽을 침범 | 절대 위치 해제, 한 행 정렬, 12~16px 내부 여백 |
| 훈련소 제목 바가 음수 마진으로 바깥 프레임과 겹침 | 헤더 음수 마진 제거, 제목·닫기 영역과 탭 간격 통일 |
| 제목 바·스크롤 영역에 이전 장식과 선이 중복 | 헤더 중복 배경 제거, 단일 프레임과 키보드 전용 포커스 처리 |
| 도감 편성 슬롯의 이름과 소환 확률 안내가 맞닿음 | 사진·이름 세로 정렬, 슬롯 높이 및 안내 간격 확보 |
| 목록을 스크롤하면 내용이 투명 탭 뒤로 비침 | 탭에 불투명 바탕과 고정 간격 적용 |
| 채용 결과 제목이 초상 옆에 붙음 | 제목·초상·이름·설명을 세로 중앙 정렬하고 하단 액션 간격 확보 |
| 비활성 주요 버튼에 어두운 글자가 남음 | 비활성 텍스트 및 내부 가격 텍스트 색상 통일 |
| 보너스 주요 버튼의 보라 배경·검정 글자 조합 | 금색 주요 액션 애셋과 대비가 맞는 글자색 적용 |
| SP와 WAVE 문구가 프레임 테두리에 걸리거나 불필요하게 개행 | 한 행 HUD와 실제 내부 여백 확보 |
| 320px에서 아이템 버튼의 글자·수량이 넘침 | 아이콘/이름 세로 구성, 수량을 내부에 배치 |
| 320px 상품 설명이 한두 글자씩 잘게 개행 | 상품 이미지·설명 다음 전체 너비 구매 버튼; 가격 2줄 부품 사용 |
| 320px 도움말 우측 그림이 본문 폭을 과도하게 차지 | 작은 화면에서 보조 그림을 숨기고 본문 폭 확보 |
| 장비·상세 하단 액션의 프레임과 내용이 밀착 | 12~16px 안전 여백과 고정 액션 간격 |
| 긴 도감 이동 버튼의 화살표만 다음 줄로 밀림 | 명시적 2줄 부품과 인라인 화살표 사용 |

기존 메뉴·라우팅·문구·저장 포맷·전투 규칙은 유지한다. 좁은 화면의 카드 내 배치는 가독성을 위해 조정했다. 한 줄 부품을 임의 개행하지 않도록 긴 구매/이동은 2줄 부품을 사용한다.

## 검증과 재현

- `after/checks.json`: 화면별 버튼 가로 넘침/화면 이탈, 실행 오류와 캡처 상태. 최종 96개 상태에서 해당 자동 검출 0건.
- `node --test tests/*.test.cjs`: 30개 통과.
- `node scripts/build-pages.cjs /tmp/visual-pass-release`: 배포 산출물에 visual-pass.css 포함.
- `node scripts/capture-visual-pass.cjs`: Playwright와 Chromium 필요. UI_BASE_URL, UI_CHROMIUM_PATH, AUDIT_PHASE로 대상/경로/단계 설정 가능. GM 상태 fixture를 사용한다.
- `python3 scripts/build-visual-review.py`: Pillow 필요. 비교 HTML과 모아보기 생성.

이 결과는 Chromium 모바일 에뮬레이션의 1차 검수다. iOS Safari 실기기, 브라우저 글자 확대, 모든 번역 언어·수치·콘텐츠 조합은 별도 검증 범위다.
